# Quickstart 验证指南: 净收入比例录入原型

**交付物**: `项目/净收入比例录入/prototypes/净收入比例录入原型.html` | **契约**: [contracts/ui-contract.md](./contracts/ui-contract.md) | **模型**: [data-model.md](./data-model.md)

## 前置与启动

- 环境：Chrome / Edge 现代桌面浏览器，无需服务器、无需网络。
- 启动：双击 HTML 文件（file:// 协议）直接打开。
- 每轮验证前：点右上「重置演示数据」回到种子态（清 localStorage）。
- 角色切换：顶部「当前视角」下拉，按场景切到对应角色。

## 验证场景（对应 spec 的 Independent Test 逐条走查）

### S1 · US1 首次确认全流程（P1）

1. 视角=银行业务部 → 工作台找状态「新增」的产品 → 点「发起首次确认」。
2. 编辑：牵头部门选银行业务部；添加 归属主体（银行业务部 60% + 北京分公司 40%）→ 合计条显示 100% 绿色 → 提交。
3. **拦截验证**：先把比例改成 60/30（Σ=90%）→ 提交按钮禁用、提示差额 10%（US1-AS4 ✓）。改回后提交。
4. 视角=客户经理 → 待办出现该流程 → 点「退回」，不填意见 → 被阻止（V6）；填意见后退回。
5. 视角=银行业务部 → 流程回到发起步骤、草稿保留 → 修改后重新提交。
6. 视角=客户经理 → 「确认无误」→ **期望**：产品徽标变「存量」、配置生效、留痕含各环节操作人与时间（US1-AS2 ✓）。
7. **再发起拒绝**：视角=银行业务部，对该存量产品再点「发起首次确认」→ 被拒并提示走调整流程（US1-AS5 ✓）。

### S2 · US2 银行部总部份额（P2）

1. 视角=银行业务部 → 「总部份额设置」→ 选银行部存量产品。
2. **参考值**：界面显示柜台管理费占比 + 「仅供参考，不自动采用」；选总管理费为 0 的产品 → 显示「参考值不可用」（E-g ✓）。
3. 设 20%（≠参考值）→ 提交 → 视角=审批人 → 通过 → **期望**：以设置值 20% 生效，参考值不参与（US2-AS2 ✓）。
4. **端点**：另一产品设 100% → 提交触发二次确认弹窗「分公司份额将全部为 0」→ 确认后放行（US2-AS5 ✓）；0% 可直接提交。
5. **漏设**：找当月未设份额的产品 → 列表高亮 + 徽标「沿用上月 {value}」（US2-AS3 ✓）。
6. **截止后改值**：把顶部月份指示切到「拆分计算已触发」→ 修改当月份额 → 弹「将触发当月拆分重算」确认（US2-AS4 ✓）。

### S3 · US3 机构/券商部门内调整（P2）

1. 视角=机构业务部 → 对机构部存量产品发起「部门内调整」。
2. 新增一个分公司归属主体并重新分配比例 → Σ≠100% 时提交被拦（US3-AS3 ✓）→ 配平后提交。
3. **实时预览**：编辑比例时预览区金额即时变化，带「试算值」角标（FR-016/017 ✓）；选无净收入数据的产品 → 显示「暂无可预览数据」且编辑不禁用（FR-018 ✓）。
4. 视角=审批人 → 「退回发起人」→ **期望**：调整单回可编辑态、现行配置不变、退回意见留痕（US3-AS2 ✓）。
5. 重新提交 → 审批通过 → **期望**：新配置生效、产品档案中旧版本可追溯（US3-AS1 ✓）。

### S4 · US4 部门间调整（P3）

1. 构造：选归属为 银行业务部 60% / 机构业务部 40% 的产品。
2. 视角=机构业务部 → 点「部门间调整」→ **期望**：拒绝，提示仅最高比例部门可发起（US4-AS2 ✓）。
3. 视角=银行业务部 → 发起 → 编辑新 rows → 提交 → 流程进入机构业务部确认环节（US4-AS1 ✓）。
4. 视角=机构业务部 → 「退回」附意见 → **期望**：整体退回发起方、确认链重置、意见留痕（US4-AS3 ✓）。
5. 重提 → 机构业务部「同意」→ 视角=创新发展部 → 归口审批通过 → **期望**：调整生效，新配置为下次拆分比例来源（US4-AS4 ✓）。

### S5 · US5 留痕与追溯（P4）

1. 完成 S1+S3 后，进入该产品「产品档案」。
2. **期望**：版本时间线 ≥3 个版本（首次确认 + 调整），每版可展开「谁、何时、场景、旧值→新值」diff（US5-AS1、SC-005 ✓）。
3. 留痕流水含退回动作与意见行（US5-AS2 ✓）；页面无任何编辑/删除控件（FR-010 ✓）。

### S6 · 横切校验

1. **在途互斥**：某产品流程在途时，再对其发起任何场景 → 弹窗提示既有流程信息（FR-013 ✓）。
2. **权限过滤**：逐一切换 7 个角色视角，核对工作台入口与待办按权限矩阵显隐（FR-012 ✓）。
3. **刷新恢复**：流程走到一半刷新页面（F5）→ 状态保持；重置后回种子态（D6 ✓）。

## 通过标准

S1–S6 全部期望行为可复现，且 E-j/E-k/E-l 相关界面均带「⚠ 待业务定稿」角标（A3/D8）。任何一条不符 → 记入 tasks.md 对应任务的返工项，不带病交付评审。
