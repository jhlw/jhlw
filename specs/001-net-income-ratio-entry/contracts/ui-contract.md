# UI Contract: 净收入比例录入原型

**Date**: 2026-09-21 | **交付物**: `项目/净收入比例录入/prototypes/净收入比例录入原型.html`（单文件）

本契约定义视图清单、每视图的交互承诺与对应验收条款。实现偏离本契约须回改契约或实现，二者保持一致。视觉基线：延续《归属比例配置流程原型.html》的 CCB 配色变量、步骤轨道、splitBar；实体与校验引用 [data-model.md](../data-model.md)（V1~V7）。

## 全局框架（所有视图共有）

| 元素 | 契约 | 验收映射 |
|---|---|---|
| 角色视角切换器 | 顶部下拉，7 角色（Role 表）；切换后入口/按钮按权限矩阵即时过滤，无需刷新 | FR-012 |
| 当前月份指示 | 显示 mock「当月」（如 2026-09）与「拆分计算触发时点」状态（未触发/已触发） | FR-009、E-j |
| 重置演示数据 | 一键回种子态（清 localStorage），需二次确认 | D6 |
| 待办角标 | 当前视角角色有待处理环节时，导航显示数量角标；点开即达待办（催办入口示意，不设自动通过） | Edge Case「长时间未处理」 |

## 视图 1：工作台（入口）

- 产品列表：代码、名称、状态徽标（新增/存量）、牵头部门、现行配置 splitBar 缩略、是否有在途流程。
- 按角色过滤可发起动作：`发起首次确认`（仅新增产品）、`部门内调整`、`部门间调整`、`总部份额设置`（仅银行部视角）。
- **V2**：点任何发起动作，若该产品有在途流程 → 弹窗提示「已有在途流程（场景、发起人、当前环节）」，不放行。
- **V3**：存量产品的「发起首次确认」不可用，悬浮提示「已完成首次确认，请走调整流程」。
- **V4**：部门间调整入口仅对 ownerDept 视角可用，其他部门点击 → 拒绝提示「仅当前归属比例最高的部门可发起」。

## 视图 2：首次确认流程（US1，scenario=first_confirm）

步骤轨道：`发起编辑 → 客户经理确认 → 生效`。

| 步骤 | 交互承诺 | 验收映射 |
|---|---|---|
| 发起编辑 | 选择牵头部门（三选一，A4）；编辑 rows：增删归属主体（部门/分公司选择器）+ 比例输入（4 位小数）；实时合计条（Σ≠100% 红色 + 差额数字）；**V1** 不满足时「提交」禁用并提示差额 | US1-AS1、AS4 |
| 客户经理确认 | cm 视角见「确认无误 / 退回」；退回必附意见（**V6**）；确认与退回均即时反映到发起人与 cm 双方的流程状态可见性 | US1-AS1、AS2、AS3 |
| 生效 | 生成 ConfigVersion；产品徽标 新增→存量；留痕写入各环节操作人与时间 | US1-AS2、FR-003 |
| 退回回路 | 回到发起编辑步骤，草稿保留，可改可重提；退回意见在留痕可查 | US1-AS3、US5-AS2 |

## 视图 3：银行部总部份额设置（US2，scenario=bank_hq_share）

步骤轨道：`设置份额 → 部门审批 → 生效`。

| 交互点 | 契约 | 验收映射 |
|---|---|---|
| 按产品设置 | 产品选择器列出银行部存量产品；每产品独立份额值（E-k/A3，界面带「⚠ 待业务定稿 E-k」角标） | US2、FR-006 |
| 参考值展示 | 只读展示「柜台管理费/总管理费」占比 + 文案「仅供参考，不自动采用」；总管理费为 0 → 显示「参考值不可用」 | US2-AS2、E-g/D3 |
| 端点值 | 0% 与 100% 均可输入；100% 提交触发二次确认弹窗「分公司份额将全部为 0」（**V5**，带 E-l 角标） | US2-AS5 |
| 审批 | 审批人视角「通过/退回」；通过后 HqShareSetting 生效、留痕 | US2-AS1、FR-007 |
| 漏设演示 | 当月未设的产品在列表高亮 + 徽标「沿用上月 {value}」（carriedOver，带 E-j 角标） | US2-AS3 |
| 截止后改值 | 「已触发」状态下修改当月份额 → 确认弹窗「将触发当月拆分重算」（**V7**） | US2-AS4、FR-009 |

## 视图 4：机构/券商部门内调整（US3，scenario=intra_dept）

步骤轨道：`编辑调整 → 部门审批 → 生效`。

- 编辑器同视图 2 的 rows 编辑（增删主体 + 比例，**V1** 含删除主体后校验 → US3-AS3）；左侧并排显示现行配置（只读）供对照。
- 审批环节「退回发起人」→ 调整单回可编辑态，**现行配置不变**（US3-AS2）；退回意见留痕。
- 通过后：新 ConfigVersion 生效、旧版 superseded、留痕（US3-AS1）。

## 视图 5：部门间调整（US4，scenario=cross_dept）

步骤轨道：`最高比例部门发起 → 涉事部门逐一确认 → 创新发展部归口 → 生效`。

| 交互点 | 契约 | 验收映射 |
|---|---|---|
| 发起资格 | 见视图 1 **V4**；发起后可编辑完整 rows（含其他部门主体） | US4-AS1、AS2 |
| 逐一确认 | 确认链按涉事部门排序展示（谁已同意/待确认/已退回一目了然）；每个部门「同意/退回（附意见）」 | US4-AS1、AS3 |
| 任一退回 | 整体退回发起方，确认链重置，重走全部确认；退回意见留痕 | US4-AS3 |
| 归口审批 | 全部同意后 innov 视角出现「归口审批」待办；通过 → 生效，新配置作为下一次拆分比例来源 | US4-AS4、FR-008 |
| 在途与计算并行 | 该产品当月拆分已触发时，界面提示「当月按已生效配置计算，本调整自下期适用」 | Edge Case、A7 |

## 视图 6：拆分结果实时预览（FR-016~018，内嵌于视图 2/3/4/5 编辑步骤）

| 契约 | 验收映射 |
|---|---|
| 编辑 rows 或份额值时**实时**重算：上月净收入（总）× 当前编辑中配置 → 各归属主体金额与占比；银行部场景额外展示「总部份额（设置值）+ 剩余份额经 R1–R3 链分配至各分公司」两级试算 | FR-016 |
| 计算调用移植的同一规则链（pct/calcProduct，Q14 精度、尾差计最大方）；结果区恒显「试算值」角标 + 页脚「试算结果不落库、不被下游引用」 | FR-017 |
| 上月净收入未上传 / 无该产品数据 → 预览区显示「暂无可预览数据」+ 原因说明；**编辑与提交流程不被禁用** | FR-018 |

## 视图 7：产品档案（US5，留痕与版本追溯）

| 交互点 | 契约 | 验收映射 |
|---|---|---|
| 版本时间线 | 左侧纵向时间线：每版本一行「谁、何时、场景、动作」；点击展开旧值→新值 diff（增/删/改的主体与比例高亮） | US5-AS1、FR-011、SC-005 |
| 留痕流水 | 全量 TrailEntry 表格（可按产品过滤）；退回动作与意见独立成行 | US5-AS2、FR-010 |
| 只读保证 | 本视图无任何编辑/删除控件；尝试通过控制台删除不在契约内（界面层示意「不可修改与删除」） | FR-010 |
| 现行配置 | 顶部展示当前生效版本 splitBar + 生效期间 | FR-011 |
