# 产品谱系与产品画像 · 同业访谈问题清单

- 日期：2026-08-28
- 用途：验证已定稿的《产品谱系及产品画像设计方案》（2026-08-14），找差距、找佐证
- 访谈原则：**先开放式提问了解现状，再针对性验证自家设计点**；避免"你们是不是也这样"式的引导性提问
- 标注说明：【开放】= 现状摸底；【验证 D#】= 针对自家设计决策点 D# 的验证（见下方速查表）；★ = 核心问题，时间不足时必问
- 建议时长：产品部 60~90 分钟；销售、投研、IT、风控 30~45 分钟
- 记录规则：每场访谈结束前，对照附录 A 打分表逐项判定"佐证 / 有差距 / 同业没做"

## 自家设计决策点速查表（D1~D21）

| # | 决策点 | 自家做法（一句话） |
| --- | --- | --- |
| D1 | 三层谱系树 | 资产大类（货币/固收/权益/多资产 4 类）→ 策略赛道 → 产品 |
| D2 | 赛道三条件 | 同一策略标签 + 同一业绩比较基准（体系一致）+ 同一投研团队，同时满足 |
| D3 | 监管分类并存 | 监管分类是产品属性字段，与谱系并存；谱系管"公司怎么看"，监管分类管"报送怎么报" |
| D4 | 谱系编码 | 大类 2 位 + 赛道 2 位共 4 位；产品部统一分配，不回收复用 |
| D5 | 产品换挂 | 需评审并永久留痕（生效日/原因/评审编号）；业绩按归属时段分段考核 |
| D6 | 赛道治理 | 新增赛道需产品部 + 风控评审；年度谱系复盘（覆盖度/旗舰/边界复核） |
| D7 | 私募扩展预留 | 节点带"产品类别"标记（公募/私募/专户），参与权限控制，不与公募树混挂 |
| D8 | 画像模板 | 四组维度（基础/投资/风险业绩/销售运营），每字段 7 项元数据 |
| D9 | 净值口径 | 所有收益率字段统一累计净值口径，禁止复权/分红另口径 |
| D10 | 同业比较口径 | 默认银河分类，用晨星须注明、不混用；排名必须注明口径四要素 |
| D11 | 双层画像 | 公司画像（8 块）在上 + 产品画像在下；销售输出"公司速览 + 产品速览卡"组合 |
| D12 | 旗舰产品 | 年度评选：同类规模前 3 或近 3 年收益前 25%，每线至多 2 只 + 明星例外提名（风控确认口径） |
| D13 | 谱系覆盖度 | 已启用赛道数 ÷ 目标版图赛道数；空白清单是产品布局候选方向 |
| D14 | 双视图投影 | 销售视图（速览卡）/ 内部视图（产品档案）同一主数据的投影，不存副本 |
| D15 | 黑名单字段 | 默认双视图可见 + 黑名单例外（客户结构、渠道业绩、内部考核仅内部） |
| D16 | 发布闸门 | 销售视图发布走审批链：产品部初审（口径）→ 风控合规终审 → 发布留档 |
| D17 | 角色分工 | 8 类内部使用者各司其职（管理层/部门总/市场/产品/投研/风控/运营/IT） |
| D18 | 数据流 | 静态字段走成立/变更流程，动态字段自动刷新，同业比较季度导入 |
| D19 | 维护分工 | 基础/投资归产品部，风险归风控，销售运营归销售/运营部，公司画像归产品部 |
| D20 | 冲突仲裁 | 来源系统为准并告警产品部复核，不静默覆盖；缺失显式标注"暂无" |
| D21 | 系统形态 | 主数据平台优先挂靠现有数据中台；路线：Excel 先行 → 平台 → 渠道接口 |

## 通用开场（所有受访者，约 5 分钟）

1. ★【开放】请介绍一下您的角色，以及日常工作与产品数据（产品资料、分类、业绩展示）的交集。
2. 【开放】贵公司目前公募产品数量大概多少只？权益、固收、货币、多资产的大致比例？
3. 【开放】如果要给新同事介绍"公司都有哪些产品、分别什么定位"，您会怎么做？（探现状载体与口头共识）

## A. 产品部（体系设计者 / 维护者，60~90 分钟）

### A1 谱系与分类体系

1. ★【开放】贵公司内部有没有自己的产品分类/组织方式？谁在维护？建成多久了？
2. ★【开放】这套分类长什么样——几层？按什么维度切分（资产类型/策略/投资团队/渠道/客群）？
3. 【验证 D1】大类层级是按资产属性分（货币/固收/权益/多资产），还是按别的（主动/被动、开放/封闭）？当时为什么这样分？
4. ★【验证 D2】中间层（策略/产品线）的划分标准是什么——投资策略、业绩基准、投研团队，还是组合？（追问：同策略不同基准、同团队不同策略的产品怎么处理）
5. 【验证 D3】内部分类和监管分类（股票型/混合型/FOF 等）是什么关系？监管分类在内部树里放在哪？报送和内部管理各用哪套？
6. ★【开放】有没有遇到产品归属有争议/模糊的情况（如固收+、养老 FOF、含权债）？最后怎么裁定的？裁定结果有没有沉淀成规则或案例库？
7. 【验证 D5】产品中途换分类/换产品线的情况有吗？流程怎么走？换线后历史业绩和考核怎么算？
8. 【验证 D4】分类节点有编码规则吗？谁分配？停用后的编码会复用吗？
9. 【验证 D6】新增一个产品线/分类节点要走什么流程？有年度性的复盘调整机制吗？
10. 【验证 D13】有没有"产品版图/布局"的概念——哪些赛道是空白、未来要补的？怎么管理这份清单？
11. 【验证 D7】私募资管/专户产品有没有纳入同一套体系？还是完全分开管理？

### A2 画像内容与口径

12. ★【开放】你们有没有"产品画像/产品档案/产品一页纸"之类的产出？主要给谁用？
13. ★【开放】里面包含哪些信息块？大概多少个字段？
14. 【验证 D8】字段是怎么定义和管理的——有统一的字段标准（业务定义、口径、必填性、来源、维护人），还是各部门各管各的？
15. 【验证 D9】业绩字段用什么净值口径（累计/复权/分红再投资）？不同材料里口径统一吗？出过口径混用的问题吗？
16. 【验证 D10】同类排名用什么分类（银河/晨星/自家定义）？对外引用排名时注明口径吗？
17. 【验证 D11】公司层面有没有标准化的"公司画像/管理人介绍"？和单产品材料是组合使用还是各自独立？
18. 【验证 D12】"旗舰/代表产品"怎么认定——量化标准还是提名制？多久评一次？有没有例外机制？

### A3 数据与维护治理

19. 【验证 D17】这套体系现在有哪些部门在实际使用？各自用哪部分？（管理层看全景 / 销售看速览 / 投研核对业绩 / 运营维护字段）
20. ★【验证 D19】产品资料的数据分别由谁维护（产品部/投研/风控/销售/运营）？集中还是分散？
21. 【验证 D18】数据从哪些系统来？自动同步和人工录入大概各占多少？人工部分怎么控制质量？
22. 【验证 D20】来源系统数据和人工录入值冲突时以哪边为准？有告警/复核机制吗？缺失数据怎么处理（留空/标注/默认值）？
23. 【开放】维护这套体系投入多少人力？各数据块更新频率（实时/月度/季度）？

### A4 评价与痛点

24. ★【开放】这套体系运转中最大的痛点是什么？
25. 【开放】如果推倒重来，您最想改哪一点？

## B. 销售 / 市场部（画像使用者，30~45 分钟）

### B1 使用场景

1. ★【开放】您平时哪些场景需要产品资料？（渠道准入申报/营销材料/路演/客户答疑）
2. ★【开放】现在从哪里拿产品资料？拿到后还要自己再加工吗（做 PPT、摘数据、算排名）？
3. 【验证 D14】对渠道/客户展示的产品资料，和内部用的产品资料，是同一套数据还是两套版本各自维护？两套的话怎么保持一致？
4. 【开放】渠道准入时对方最常要哪些信息？哪些信息最难及时拿到？

### B2 内容有效性

5. 【验证 D11】给渠道介绍时是"先公司、后产品"的顺序吗？公司层面的介绍材料有标准版吗？
6. 【验证 D10】营销材料里引用同类排名用什么口径？合规对排名表述有硬性要求吗？
7. 【验证 D12】对外主推的"旗舰/重点产品"名单是谁定的？销售侧有话语权吗？多久更新一次？
8. ★【开放】现有产品资料里，哪些字段是渠道真正会看的？哪些是没人看的摆设？

### B3 权限与发布

9. 【验证 D15】给渠道的版本里，内部敏感数据（渠道业绩、客户结构、考核数据）怎么隔离——单独做对外版、打码、还是靠流程约束？
10. 【验证 D16】对外材料发布前过什么审核流程？一般多久能出？
11. ★【开放】您觉得现在产品资料最大的缺口是什么？

## C. 投研 / 基金经理（被分类者，30~45 分钟）

1. 【开放】您了解自己管理的产品在公司内部被归到哪个类别/产品线吗？这个归属是谁定的？
2. ★【验证 D2】您觉得按"策略内核"归类合理吗？您管理的产品里有没有归得不贴切的？（追问：同策略不同基准、同团队多策略的边界情况）
3. 【验证 D5】经历过产品被调整分类/换线吗？事先会征求投研意见吗？对考核有影响吗？
4. 【验证 D9/D10】材料里的业绩和排名数据，您核对过吗？口径（净值、同类定义）和您自己算的一致吗？
5. 【开放】"投资策略描述、资产配置区间"这些内容是投研提供的还是产品部/市场部写的？准确度如何？
6. ★【开放】从投研角度，您希望产品画像里增加什么信息？

## D. IT / 数据团队（实现者，30~45 分钟）

1. ★【开放】产品主数据/产品资料目前在什么载体上（自研系统/BI 报表/Excel/供应商产品）？
2. 【验证 D21】如果自研：挂在数据中台还是独立系统？建设周期多长、投入多少人？
3. 【开放】和哪些系统集成（TA、估值/净值、投资交易、CRM、数据中台）？
4. 【验证 D18】字段数据怎么接入——直连同步/批量导入/人工？自动同步的脏数据怎么处理？
5. 【验证 D15】权限怎么实现（角色级/字段级）？对外发布版本怎么管理？
6. 【开放】这套系统用户量和访问频率什么量级？哪个功能用得最多？
7. ★【开放】建设过程最大的坑是什么？业务侧配合度如何？

## E. 风控合规部（可选，如对方安排了对应角色）

1. 【开放】产品资料/营销材料对外发布前，合规审核的职责边界是什么？
2. 【验证 D16】审核主要关注哪些点（业绩口径、排名表述、风险揭示）？审核周期一般多久？
3. 【验证 D15】内部敏感数据（客户结构、渠道业绩）对外隔离，合规有什么硬性要求？
4. 【开放】有没有遇到过材料出合规问题的情况？根因是数据错、口径错还是表述错？

## 通用收尾（所有受访者）

1. ★【开放】如果只允许改进一件事，您最希望改进产品分类/产品资料的哪一点？
2. 【开放】贵公司还有谁在这块值得我去聊？（滚雪球推荐）

## 附录 B：调研对象建议

- 公司类型：头部公募 2~3 家 + 同梯队 2~3 家 + 特色公司（固收强/量化强）1~2 家
