## G1 定位与交付形态

**Q：这套东西到底是什么？给谁用？**
→ 公司**产品主数据标准**，一体化方案：公司画像为全景、谱系为骨架、产品画像为血肉；一处定义、两处使用，杜绝两套数据打架。两阶段交付：第一阶段业务规范（谱系+模板），第二阶段系统概念设计（不细化页面与接口）。产品范围公募为主，谱系预留私募资管/专户扩展位。画像用途销售与内部兼顾：**一个模板、两个视图**。

## G2 整体架构：3 组件 + 1 横切

**Q：组件间什么关系，谁包含谁？**
→ 从大到小三层 + 一条横切：公司画像（全景，最上层）→ 产品谱系（版图骨架，中层）→ 产品画像（单产品实例，底层）；画像模板横切贯穿（只定义字段，不含数据）。视图是字段投影，不存数据副本。

## G3 谱系设计

| 拷问点 | 定稿结论 |
| --- | --- |
| 分几层 | 资产大类 → 策略赛道 → 产品，三层；产品**必须且只能挂靠一个**策略赛道 |
| 大类怎么划 | 四类：货币 10 / 固收 20 / 权益 30（含混合）/ 多资产·其他 40（QDII/另类/FOF） |
| 归属冲突 | **资格识别优先**（养老目标基金资格 → 权益类 FOF 养老赛道），其余按策略归属；重叠冲突产品部+风控评审裁决，结果沉淀谱系案例库 |
| 入赛道条件 | 三条件同时满足：同一策略标签 + 同一业绩比较基准（体系一致即可）+ 同一投研团队；团队拆分或基准重大变更触发重组评审 |
| 编码规则 | 大类 2 位 + 赛道 2 位共 4 位；私募/专户预留 `5x`/`6x` 独立段；产品沿用基金代码不重造；编码一经启用**不回收复用** |
| 监管分类放哪 | 作为产品节点**属性字段与谱系并存**：谱系管"公司怎么看产品"，监管分类管"报送怎么报产品" |
| 换挂治理 | 不允许单方调整；评审 + 永久留痕（生效日/原因/评审编号）；业绩考核按"归属时段 × 赛道"分段；**赛道整体换大类属年度复盘边界复核，不设日常入口** |

## G4 画像模板

**Q：画像长什么样，字段怎么管？**
→ 四组维度：基础（骨架，双视图均见）/ 投资（销售取精炼版）/ 风险+业绩（动态，口径分级）/ 销售+运营。每字段必带 **7 项元数据**（字段名、业务定义、数据类型、枚举值、必填性、来源与维护、适用视图）。枚举权威来源：风险等级采监管适当性 R1-R5；策略标签由产品部定义、风控会签，变更走版本管理。字段全集 v1 由联合工作坊补全（产品部牵头，分维度组组织），v1 定稿即基线。

## G5 视图与字段边界

**Q：两套视图会不会变成两套数据？**
→ 不会：销售视图（速览卡）与内部视图（产品档案）是**同一主数据的投影**，任何字段值只有一份。字段边界规则：**默认双视图可见 + 黑名单例外**（客户结构明细、渠道业绩、内部考核数据仅内部），规则先行，不逐字段审批。

## G6 公司画像

**Q：管理人层面放什么，敏感怎么分级？**
→ 8 块：基本情况、经营概况（含谱系覆盖度）、业绩与同业、销售渠道、旗舰产品、客户结构、规模趋势、关系联动。旗舰产品**年度评选**，量化标准：同类规模前 3 或近 3 年收益率同类前 25%（累计净值口径），每大类至多 2 只；明星产品可例外提名（风控确认口径）；旗舰信息直接引用产品画像，不存副本。渠道业绩/客户明细仅内部；销售视图只展示占比结构。

## G7 口径（全局红线）

| 拷问点 | 定稿结论 |
| --- | --- |
| 收益率 | 一律**累计净值口径**，禁止复权/分红另口径 |
| 同业分类 | 默认**银河证券分类**；个别场景用晨星须在字段注明体系，不得混用 |
| TOP 排名 | 必须注明统计口径四要素（分类标准、统计区间、样本数量、数据截止日）；不在样本内标"区间不足，未入榜"而非留空 |
| 缺失 | 第三方数据缺失显式标注"暂无"，禁止留空或伪造默认值；无同类可比时降级并说明分类口径 |
| 口径联动 | 公司画像与产品画像的排名必须同分类口径、同数据时点 |

## G8 数据治理

**Q：来源系统与画像值打架听谁的？**
→ 以**来源系统为准并告警产品部复核**，不静默覆盖；人工录入字段以审批记录为准。销售视图发布走审批链：产品部初审（口径与数据）→ 风控合规终审 → 发布，每版本留档。维护分工：基础/投资归产品部、风险归风控、业绩+同业归产品部（投研支持）、销售运营归销售/运营部、公司画像归产品部（季度）。

## G9 使用者与权限

→ 内部 8 类（管理层/部门总/市场部/产品部/投研/风控合规/运营/IT），外部 2 类（代销渠道消费销售视图、监管审计仅要求口径兼容）。私募扩展时产品类别标记参与权限控制。

## G10 系统形态与路线

**Q：建成什么形态，怎么落地？**
→ 主数据平台（核心）+ 视图服务，**优先挂靠公司现有数据中台**；无中台则独立建主数据模块但仍按中台式分层设计，避免孤立单业务系统。路线：① 谱系与模板结构化（Excel/轻应用先行）→ ② 主数据平台 → ③ 渠道输出接口。本阶段只出到概念设计（7 实体 + 7 功能模块 + 分层架构）。

## G11 范围外（YAGNI）

→ 明确不做：系统落地阶段的页面原型与接口字段定义；客服/投资者关系单独视图（从销售视图读取）；合规尽调资料（走既有合规流程）；ESG/资质清单/品牌叙事（如需以字段组扩展）。

## 附：界面原型迭代中确认的设计点

原型以建信基金 2026Q2 真实公开数据为实例，多轮迭代确认（归档 `prototypes/`：速览页 v14、谱系页 v6、画像页 v16、平台合成版、规模归因）：

- **图表化优先**：文字压减，标记符号表意（⭐旗舰 / 红点小微 / 虚线空白）
- **风险揭示用规模水位图**（产品规模条 + 清盘预警线，小微/已清盘/缩水三级）
- **产品查询三路径**：搜索直达 / 谱系三级下拉 / 最近查看
- **治理按钮内嵌行内**（大类行"＋新增赛道"、赛道行"⇄产品换挂"），覆盖度指标行常驻
- **双视图同页 tab 切换**，内部专属字段红色虚线框标注
- **亮点数字必带口径三要素**（是什么 / 什么口径 / 截止日）；真实数据与示例数据明确区分标注
