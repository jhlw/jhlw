# 银行部拆分：总部份额可设置，剩余份额按数据纯规则计算

银行部专户产品的净收入拆分长期由创新发展部线下手工完成（xlsx 需求原文写「银行部根据客户管理需求调整归属及比例」，暗示银行部全面手工调整）。定稿决策：拆分为两个正交部分——**总部份额（总部比例）由银行业务部设置**（每产品一个值，每月可调，即 xlsx C5 所指的月度调整）；**剩余份额（1 − 总部比例）由系统按分行销量/管理费数据经「分行→分公司映射」纯规则计算分配至各分公司**，无任何人工干预。分公司之间不接受手工比例，这是与被否方案（系统算建议值＋银行部可微调每个分公司份额，即"c 方案"）的本质区别。

## Considered Options

- 全手工（现状 / xlsx 字面义）：否——银行部逐分公司手工设比例无法逐月对齐实际销量，且创新发展部代拆的中间环节正是要消灭的对象。
- 全自动含总部份额（柜台管理费占比自动定为总部份额）：否——总部份额承载客户管理诉求（如总部维护的大客户倾斜），必须保留人工决定权。
- 总部可设＋剩余纯计算（定稿）：人工只出现在一个杠杆点，其余由数据推导，可复核、可重算。

## Consequences

- xlsx C5 需求文字须改写为「银行部设置总部比例并提供销量及管理费数据，系统按剩余比例计算各分公司份额」。
- xmind 原混合产品公式「直销总占比×直销内部占比＋代销总占比×代销内部占比」失效，替换为「总部比例＋(1−总部比例)×分行数据内部占比」；柜台（直销）管理费占比可作为总部比例的参考默认值（待定稿，见待确认清单）。
- 主数据（分行→分公司映射、代销渠道清单）由银行业务部维护。
- 考核口径一经年度确认（快照），历史月重算须计划财务部＋创新发展部双批准。
