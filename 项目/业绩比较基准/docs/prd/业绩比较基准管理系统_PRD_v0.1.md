## 1. 概述

### 1.1 背景

监管在 2025–2026 年密集落地"业绩 vs 基准"对照披露的硬性要求：《推动公募基金高质量发展行动方案》（2025-05）要求综合展示业绩比较基准对比；《公开募集证券投资基金业绩比较基准指引》（2026-01 发布、03 施行）第十六条要求展示过往区间业绩时**同一位置同时展示对应基准表现**（公司所有产品，除 REITs），配套过渡期 **2027-03-01 前必须完成改造**；定期报告准则与 XBRL 模板修订新增 7 年/10 年中长期区间、取消 1 个月短期业绩。

现状（证据：澄清清单 Q47、Q46 业务回复）：官网目前**没有**该类数据，属全新建设，不存在两套数据并存的过渡期；内部现有 VBA 工具（`A股基金业绩数据更新VBA.xlsm`）人工跑算，已知第 5 成分权重取列缺陷，且无法覆盖全部产品日频序列与官网/APP 推送。业务方（投资风险部）2026-10-14 口述定稿三条业务目标，2026-11-11 将目标二由"透传净值增长率"调整为"获取净值信息、产品系统自算净值收益率"。

### 1.2 一句话定位

业绩比较基准管理系统是面向**投资风险部经办/审核与全行业务查看者**的公募基金业绩数据后台，统一计算全部产品的基准收益率与净值收益率日频序列，经复核后推送官网/APP，满足 2027-03-01 监管对照披露硬时限。

## 2. 用户与场景

### 2.1 用户画像

经办/审核为投资风险部专岗，每日处理跑批告警与维护单，熟悉基金合同基准条款但不承担开发；业务查看者覆盖投研、市场、客服等，只读查询与导出，技术程度低，依赖界面口径速览理解字段；运维收件人（金科/网金/FA）按告警类型处置数据到位与系统异常。

### 2.2 用户旅程

**每日跑批旅程**：T 日估值完成 → 净值信息＋行情到位（20 点首次跑批）→ 按基金粒度齐套检查 → 齐套即算（净值收益率自算＋成分日收益＋组合合成）→ 独立复核 → 业务异常人工确认 → 推送官网/APP → 查看者次日查询。流失点：缺数基金挂起「数据未齐」，21 点未到位告警、22 点二次跑批后统一告警；异常日及其后基准累计增长率/每日超额显示「—」，净值侧照常。

**维护旅程**：告警/发现异常 → 经办发起维护（补录＋原因＋紧急程度，可批量导入）→ 审核通过/退回 → 生效入库 → 受影响基金重算 → **无论有无差异均重推**（C6/Q36，2026-11-23 定夺）→ 全程留痕。配置变更旅程同构，另加版本化截断与历史追溯重算评估。

### 3.2 详细说明（仅 P0/Must）

**F1 计算引擎（六步骤）**
- 前置：指数库＋产品基准配置已生效；净值信息（C1）与行情（C5/人工维护）到位。
- 主流程：按基金粒度齐套检查 → 以估值系统净值日期序列为基准日期轴（A股/自然日/QD 三类日历）→ 净值收益率自算（30 位）→ 成分日收益（指数点位自算 8 位；利率分段计提，2026-07-01 前 /360、起按**当年实际总天数**）→ 当日合成 R＝Σw·r（每日再平衡）→ 逐日连乘 ∏(1+R)−1 → 独立复核 → 发布。
- 分支：货基 R(t)＝万份收益÷10000、自然日序列、节假日万份收益合并至节后首个工作日；QDII 含美股要素 T+1 出具；境外休市退化为纯汇率效应（人民币计价港股指数例外，严格 0）；季末年末非交易日取最近披露日点位＋同日汇率，每季末必须披露。
- 异常：任一成分缺行情/缺净值 → 阻断该基金＋告警，不阻塞整批；修复后自动重算。异常日及其后基准累计增长率/每日超额不输出（显「—」），净值收益率各列照常。
- 空状态：无基准产品仅算/推净值收益率；基金无净值日基准收益不累计（Q18/Q37）。
- 权限：计算由调度触发，人工干预仅经维护/确认清单流程。
- **舍入链纪律**：成分先舍入 8 位再合成/连乘，Python/引擎实现必须与样例 Excel 公式链逐步同构（000270 曾因此差 ~6e-5%）；净值侧中间结果 30 位。

**F2 产品基准配置（版本化＋追溯重算）**
- 前置：产品已入库（可选运作期公募产品、母份额）；成分已在指数库。
- 主流程：发起（权重实时汇总＝100%，≠100% 红色提示阻断提交；利率类调整点带符号录入，指数类显「—」；成分至少一条）→ 审核（快照比对，退回意见回第一步）→ 生效：新版本生效日起旧版本生效止自动截断为前一日 → 历史区间按当时生效版本计算 → 触发追溯重算评估 → 重推受影响数据。
- 分支：跨版本区间自然拼接（生效日前旧版、起新版）；过合同生效日未配置 → 系统自动补算并推送（§5.4）。
- 异常：删除走审批，删除后无基准、仅推净值收益率，历史归档可查。
- 权限：投资风险部经办发起、同部门审核（审核页面同经办界面）。

**F3 行情维护与重算重推**
- 前置：指数/指标已在指数库；维护原因必填。
- 主流程：多行录入或批量导入（模板含表头示例行，校验列数/日期/代码/数值，回填后可继续增删改）→ 提交审核 → 复核生效 → 受影响基金重算 → **无论重算前后有无差异均重推官网/APP**（C6/Q36，2026-11-23 定夺，原 0.01 个百分点门槛已取消）。
- 分支：利率同一代码仅新增模式（利率代码＋生效起为键，原分段生效止自动截断，天数基准按生效日自动判定）；汇率来源固定央行中间价（直接汇率、估值日当日），维护记录生效前不进入计算；指数漏更按交易所收盘数据补录。
- 异常：汇率 T 日 17:00 前未随行情包到位 → 告警＋人工补录；折原币点位仅查询展示，缺失显「—」。
- 权限：经办发起、审核生效；维护记录查询各页签默认日期倒序。

**F4 净值收益率自算（含权益事件还原）**
- 前置：估值系统净值信息日频到位（单位净值、累计净值、万份收益（货基）、分红/份额折算事件；全精度、A/C 份额按代码独立）。
- 主流程：R(t)＝(单位净值(t)＋每份分红(t))÷单位净值(t−1)−1；折算日先按 k＝折算后份额÷折算前份额还原再加分红；1＋R；累计自基金合同生效日（含当日）逐日连乘；30 位舍入。
- 分支：货基万份收益口径（见 F1）；分母取上一净值披露日净值；仅在基金当日有净值的日期计算。
- 异常：估值修订 → 影响评估 → 重算 → 无论有无差异重推 → 留痕（Q36）；修订记录保留历史版本、留档不覆盖。
- 验收锚点：000270 样例净值序列全期累计 75.986795%，首行 R＝1.0584/1.059−1＝−0.0567% 与披露日增长率一致；分红/折算连续算例（v2.7 §4.1 D1–D4 表）逐位通过。

**F5 推送服务（官网/APP）**
- 前置：复核通过；推送方式/频率/对账细节〔待确认：C2/C3/C4〕。
- 主流程：每个净值披露批次推送①净值收益率＋③基准收益率**日频序列**（曲线数据），两端同源同批次；特殊披露频率产品（周频/月频/QDII）按各自披露日随批；封闭期按净值披露频率推送〔待确认：封闭期方案二选一〕。
- 分支：重算即重推（F3）；清盘基金按清盘公告日移出推送、历史归档可查。
- 异常：推送失败重试与差错撤回〔待确认：C4〕；区间内任一日挂起则该区间不输出并随批告警（v2.7 §4.2.2 区间口径规则 3）。
- **范围纪律**：仅推日频①③，不推 10 区间指标、波动率②④、差值⑤⑥、基准文案（Q41）。v2.7 §3.2 步骤6/§3.3/§5.3 残留"区间收益率推送"表述与 Q41 冲突，见附录 8.2-①，**开发按 Q41 执行，除非业务另行定夺**。
- 边界：本项目至推送/API 提供＋联调支持；前端"同位置展示"改造由各端条线负责（Q44）。

**F6 告警通知与前台配置**
- 触发（v2.7 §5.2 通知表，暂定）：20 点首次跑批；21 点前未获取指数/利率/汇率 → 告警（投资风险部＋金科）；21 点前未获取净值信息 → 告警（FA＋金科）；22 点二次跑批后统一告警"未到达指数＋未生成结果"（投资风险部＋金科＋网金）。
- 方式：短信＋邮件，当天不重复；收件人前台可配置；预警时间配置入口前台可调整（2026-11-19 定夺）。
- 异常：告警发送失败须留痕并重试〔假设：重试策略待技术设计〕。
- 空状态：配置屏原型未承载（用户已定夺原型维持现状），开发须补设计〔待确认：载体〕。

**F7 历史数据初始化与回补**〔待确认：范围与责任〕
