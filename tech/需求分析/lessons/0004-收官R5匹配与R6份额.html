收官：R5 匹配拆分与 R6 总部份额

约 15 分钟 ｜ 上接 课 0003 · 三表见共性 ｜ 实战素材：净收入拆分 R5 / R6 / Q13 / Q30

六条规则配表的最后一课。规矩变了：R5 没有参考表——R1 到 R3 你都是对着我的答案核，这次你先写、回传、我核对后才落库。这是「会看表」和「会写表」之间的那道门。

§1热身：换一条规则，发生器怎么用

R5 自己不做除法——占比已由 R1–R3 算好，R5 只做匹配和乘法。三个发生器里，R5 的新主力是？

  • a除法与并列尾差族
  • b外部参照与匹配缺失
  • c分组与单行退化族
b——匹配是最强的外部参照：两张表互为参照物，任何一边多出、少掉、对不上号，都是结构性边界。除法族（E-a 并列、E-g 除零）在上游 R1–R3 已拦截，轮不到 R5；分组退化同样上游已处理。发生器清单是按规则骨架勾的，不是按记忆套的。

§2R5 是什么：匹配 ＋ 乘法 ＋ 补数

规则原文（需求 xlsx · 处理规则 sheet）：

R5 净收入匹配与拆分：净收入表（③）匹配到专户数据更新的净收入（总）；净收入拆分＝收入占比×净收入（总）；与 able 源 sheet 对比，缺少的产品补入。（计算与缺数补全 · Q13） 三个动词：匹配（净收入表③ ⏤ 专户数据更新）、乘（占比×总额）、补（对 able 源 sheet，缺的产品补入）。

结构对比前五张表：R1–R3 是「归一化除法」，R5 是「匹配 ＋ 乘法」——它把 R1–R3 的输出当输入（跟 R3 的手法一样），再加上第三个参照物 able 源 sheet。边界几乎必然长在「匹配」上：两表各一翼，一边有一边没有。

给 R5 挑边界例，下面哪一行最值得进表？

  • a净收入金额巨大的老产品
  • b只在一张表出现的产品
  • c净收入行数很多的产品
b——「只在一张表出现」有两个方向，各值一行：净收入表（③）有、专户数据更新没有（新品？销量漏报？→ 无占比可乘）；专户数据更新有、净收入表没有（→ 无总额可拆，Q13 的补数正是补这边）。a 是量级（乘法对它同样免疫），c 是行数规模，规则无感。

§3独立产出：R5 三行表（无参考，回传核对）

给 R5 写三行：1 个正常例 ＋ 2 个边界例。格式沿用「产品××××××：…… → 期望输出 ____」。写完展开自查清单，勾完把三行贴回会话——我核对通过后才落库。

自查清单（这课没有参考表，用这个代替）：

  1. 正常例的输出算到了具体金额吗？（占比×净收入总额，算到元，别只抄公式）
  2. 两个边界例是否都打在匹配的结构上？（一边有一边没有／匹配键不规范——而不是量级）
  3. 有没有一行考虑净收入（总）为 0 或为负？（乘法的新端点：拆出 0 元、或负总额×正占比＝负金额）
  4. 每行「待确认」是否标了核实对象？（提示：净收入表归口是谁，Q13 的 able 对比谁来核）
  5. Q13 补数的方向说清了吗——从 able 补进哪一张表、补的是产品还是金额？

五项全勾，贴回来。核对意见会直接标在你那三行上；通过后我落 docs/R5-匹配拆分-例子表.md，新待确认从 E-h 起编号。

§4R6 总部份额：一次乘法，一个已定稿的口径

R6 总部份额：银行部每月设置总部份额（界面展示柜台占比参考值，不自动采用）；R1–R3 算得的地区占比×（1−总部份额）分配至分公司。（目标系统模型 · Q30 融合，ADR-0001）

走查（接 0003 的 536392）：银行部当月设总部份额 20%，界面参考值显示柜台占比 15%——以 20% 为准：

步骤算式结果
北京分公司0.5300 ×（1−0.2000）0.4240
上海分公司0.4700 ×（1−0.2000）0.3760
合计校验0.4240＋0.3760＋总部 0.20001.0000 ✓

注意 R6 的例子表会出现第一行「已定稿」的边界例：参考值 15% ≠ 设置值 20% 时以设置值为准——这不是待确认，是 ADR-0001 定死的口径。例子表的另一半价值正在这：不只暴露未知，还锁定已知——已定稿的行放在表里，回归测试和后来人都有据可查。真正的待确认只剩端点：份额设 100%（分公司全 0）允许吗、设 0%（纯 R1–R3）呢。

银行部当月设总部份额 20%，界面参考值 15% 未采用。536392 经 R3 算得北京 0.5300 / 上海 0.4700。手算两分公司最终比例并校验——顺带答：为什么不用 15%？

北京＝0.5300×0.8000＝0.4240；上海＝0.4700×0.8000＝0.3760；校验：0.4240＋0.3760＝0.8000，＋总部 0.2000＝1.0000 ✓。不用 15%：ADR-0001 的核心决策——总部份额承载客户管理诉求（C5 原意），柜台占比只是参考展示，不自动采用。你若顺手答出「这是已定稿行不是待确认行」，说明你已经在用「锁已知」的眼光看表了。
