# 02《掌握需求过程》精读指南

> 原名 *Mastering the Requirements Process: Getting Requirements Right*（第 3 版），Suzanne Robertson & James Robertson，2011。有中译本《掌握需求过程》。配套 Volere（volere.org）提供免费的需求模板与需求壳下载。
>
> 📖 电子版渠道与全书逐章解析见 [../reference/掌握需求过程-全书解析.md](../reference/掌握需求过程-全书解析.md)（微信读书有第 3 版）。

## 一句话定位

Volere 需求过程：一套**需求的记录格式（需求壳）、分类体系（27 类）、验收标准写法（fit criterion）和完整性检查清单**——管的是"问出来的答案怎么落成不漏、可测、可追溯的需求条目"。

## 它解决你哪个问题

题库管"问什么"，拷问定稿管"决策是什么"，但两者之间没有结构化的**需求条目载体**：一条需求写下来时，谁提的、为什么、怎么算满足、优先级多少，散落在 Q 编号、C 编号、ADR、xlsx 各处。Volere 的需求壳就是给每条需求一个统一的"壳"，和你的题库方向完全契合——一个管输入（问），一个管输出（记）。

## 核心工具一：需求壳（Requirement Shell）

每条需求一个壳，关键字段：

| 字段 | 说明 | 你的项目示例 |
|---|---|---|
| 唯一编号 | 如 `REQ-净收入-014` | — |
| 需求类型 | 27 类之一（见下表） | 计算规则 |
| 描述 | **The system shall ...** 一个"shall"一句 | 系统应在全部输入到齐后一次性计算当月拆分 |
| 理由 Rationale | 为什么有这条（没有它就无法判断变更时该不该保留） | 避免部分输入下反复重算产生不一致版本（Q21） |
| 来源 Source | 谁提的：人/部门/文档页码 | 净收入拷问定稿 Q21，2026-09-08 |
| **验收标准 Fit Criterion** | 可测量的通过条件（灵魂字段，见下） | 计算完成时间戳后，任何比例修改不得改变当月结果，只能走重算审批 |
| 顾客满意度/不满意度 | 实现了加几分 / 不实现减几分（量化优先级用） | +3 / −5 |
| 优先级 | 与满意度指标配合 | 高 |
| 支持材料 | 例子表、ADR、报文样例链接 | ADR 0001、三栏例子表 |

注意与 ADR 的分工：**ADR 记"为什么选这个方案"（决策），需求壳记"系统要做什么、怎么算满足"（条目）**。一条 ADR 常展开成多个需求壳。

## 核心工具二：Fit Criterion——把模糊词改成可测量

书里最值得背下来的技术。三步：

1. 圈出描述里的**模糊词**（快、友好、及时、灵活、稳定、充足……）
2. 对每个模糊词问：**拿什么测量它，谁拿什么仪器在什么条件下读到什么数？**
3. 把答案写进验收标准，模糊词即可留给人、测量值留给机器

改写示例（取自你两个项目）：

| 模糊描述 | 模糊词 | Fit criterion |
|---|---|---|
| 银行部"每月"设置总部份额 | 每月 | 每自然月 1—5 日内可设置；6 日 0 点未设置则沿用上月值并告警 |
| 公告发送要"及时" | 及时 | 公告官网挂出当日 8:00 前批处理发送，最迟 14:00；14:00 后不得发送当日文件 |
| 缺数"不阻塞"计算 | 不阻塞 | 任一产品缺净收入或比例时，其余产品照常计算并出结果；缺数产品列入缺数清单，清单当日生成 |
| 曲线口径"基本一致" | 基本一致 | 同一产品同一起止日，我方 F33 报送涨跌幅与建行展示曲线差值 ≤ 1bp |

写不出 fit criterion ＝ 需求还没拷问到位——这条本身可回填题库（追问链最后一问："这条怎么测？"）。

## 核心工具三：27 类需求类型（归组速查）

功能类之外，非功能常被漏——这也是完整性检查的用处。归组：

- **功能**（10 类）：行为、事件响应、数据、约束的变通……
- **外观/界面**、**易用性**、**性能**（速度/容量/精度——你的 4 位小数属此类）、**可伸缩性**、**可维护性**、**安全**、**文化与政策**（监管口径属此类——金规〔2025〕6 号）、**法律**、**可移植性**……
- 另有**项目约束**（预算、时限——对应披露 C14 上线时限无明文）与**项目界面**类

用法：定稿后逐类扫一遍，"这一类有没有需求？"——和题库的类别遍历同一套思路，一个管提问一个管落条目。

## 核心工具四：项目启动（Blast-off）与业务事件

- **启动会**定五件事：目标、干系人、术语初版、约束、范围——你的拷问定稿会 Q1（交付物）、Q2（部门范围）就是干这个
- **业务事件**分析：找"外部世界发生什么、系统必须响应什么"（月初计财上传净收入→触发计算），事件列表天然划分需求包，也是缺需求的探测器

## 精读路径

1. **第 1~4 章**（过程总览 + 需求壳 + fit criterion）：精读，工具书式反复用
2. **需求类型章节**：略读 + 把归组表复印在手边
3. **收集技术章节**（访谈、研讨会、观察）：结合第 3 本一起看，此书略读即可
4. **完整性/一致性/复用章节**：第 12 章前后，精读"遗漏检测"部分
5. 跳过：与具体过程管理、迭代排期强相关的章节
6. **下载 volere.org 的免费模板**（需求壳 + 规格模板），比抄书快
