# 需求拷问题库

跨项目复用的需求拷问题目。每题四字段：**问**（照着问）、**适用**（何时触发）、**追问链**（追到底的路径）、**来源**（真实出处，题库的灵魂）。

## 用法

新需求拷问时的开场提示词：

> 读 `docs/需求拷问题库.md`，对本需求按类别逐题过一遍，不适用的说明原因跳过，新问题按题库格式记录，定稿后列出题库里没有的新题供回填。

## 维护规则

- **只增不删**；过时的题标 `[已过时]` 留着，不删
- 回填时机只有两个：**拷问定稿当天**（AI 对比题库列新增题）、**缺陷复盘时**（UAT/上线问题回溯"当初该问没问的"）
- 类别不够用就新增一类；题号类别内顺延
- 来源必须真实可溯；由既有题目引申的标注〔引申〕

## 一、口径类

### 口径-01 每项数值输入的来源、版本与时点
**问**：这个数值从哪来（系统报表 / 邮件 / 口头）？以哪个版本为准？每月几号、谁提供？
**适用**：任何以数值为输入的规则
**追问链**：数据在来源系统的确切路径与表名 → 提供迟到/重发怎么办 → 是否有替代来源
**来源**：〔净收入〕输入数据清单①-⑥——销量表为邮件人工提供、管理费表在 able 系统有确切路径、净收入表为计财部月初第 2 个工作日上传；产品信息表走接口同步（Q33/C5）

### 口径-02 同名异义与跨体系术语
**问**：需求中的关键名词，在我方与合作方体系中含义是否一致？
**适用**：涉及外部机构（银行渠道、监管、集团内其他公司）的需求
**追问链**：本方叫法 / 对方叫法分别是什么 → 材料中混用时以哪个为准 → 术语表登记 Avoid 项
**来源**：〔净收入〕Q8/Q31——我方"分公司" vs 建行体系"分行"；销量表"分行"与管理费表"名称（地名）"须统一归一为"地区"再映射（CONTEXT.md 已登记 Avoid）

### 口径-03 源材料互相矛盾时以谁为准
**问**：需求方提供的多份材料（xlsx / xmind / 口头说明）对同一规则说法不一致时，以哪份为准？另一份怎么处理？
**适用**：任何有书面材料的需求
**追问链**：矛盾点是口径差异还是笔误 → 需求方确认后是否书面定稿 → 勘误要不要留痕
**来源**：〔净收入〕ADR 0001——xlsx C5"银行部手工调整"与 xmind"按销量管理费计算"矛盾，定稿为混合模型（总部份额可设置＋剩余纯计算）

### 口径-04 "按 X 计算"的 X 到底是什么
**问**：书面依据里"按估值表数据""按销量"这类表述，精确指哪张表、哪个字段、哪种口径？
**适用**：任何引用监管文件 / 渠道通知 / 业务惯例的计算规则
**追问链**：字段存在多种口径时选哪个 → 每个候选的含义与副作用 → 选择理由记 ADR → 对方是否可能理解不同
**来源**：〔披露〕ADR 0001——通知要求"按估值表数据计算收益率"但未指明净值口径，定稿累计净值（单位净值会把分红误算为下跌）；C5 建行自算曲线口径待对齐

### 口径-05 阈值与档位判定的基准
**问**：档位切换以什么基准日期、什么日历、哪一刻切换？
**适用**：含分档 / 阈值 / 档位切换的规则
**追问链**：基准日（合同生效日 / 成立日）→ 自然日还是交易日 → 满 **当日** 还是次日切换 → 切换前后各是什么档
**来源**：〔披露〕C2——固收 1 个月 / 1 年、非固收 6 个月档位：按基金合同生效日、自然日、满的当日切换

### 口径-06 量纲是否需要统一
**问**：不同环节用不同量纲（如销量 vs 金额），维持差异还是统一换算？
**适用**：多输入源聚合计算的规则
**追问链**：差异是否有业务理由 → 统一的代价与收益 → "维持现状"是否记为显式决策
**来源**：〔净收入〕Q32——直销内部占比用销量、代销内部占比用管理费，维持现状口径、不设统一计划

## 二、边界异常类

### 边界-01 缺数怎么处理
**问**：每类输入缺数时系统怎么办？
**适用**：依赖多方输入的计算或报送
**追问链**：缺数分类列举 → 列缺数清单还是报警 → 阻塞全局还是跳过该对象 → 补数后如何重算 → 映射表缺一档算不算缺数
**来源**：〔净收入〕Q13——缺净收入、缺比例两类，系统列缺数清单，不阻塞已有产品计算

### 边界-02 精度、尾差与合计校验
**问**：数值精度保留几位？合计不齐时尾差给谁？输出是否带校验？
**适用**：任何比例 / 金额拆分计算
**追问链**：显示精度与计算精度是否一致 → 尾差规则（计入最大方 / 末位方 / 指定主体）→ 合计 = 100% 或总金额的校验放在哪一环
**来源**：〔净收入〕Q14/Q20——比例保留 4 位小数、尾差计入占比最大方；导出含金额＋比例＋合计校验

### 边界-03 重复提交与覆盖规则
**问**：同一对象重复提交 / 发送时以谁为准？
**适用**：有报送、上传、可重复操作的流程
**追问链**：后到覆盖还是拒绝 → 覆盖是否留痕 → 部分重复（同对象不同内容）怎么算
**来源**：〔披露〕C9——公告重复发送，默认后到为准

### 边界-04 封闭清单还是动态识别
**问**：特殊对象的识别，是维护封闭清单还是按数据动态判断？
**适用**：存在"特殊产品 / 客户 / 渠道"分类的规则
**追问链**：清单谁维护、多久更新 → 漏识别 / 误识别的后果 → 数据可判断时为何还要清单
**来源**：〔净收入〕Q35——混合产品按管理费表两销售商并存动态识别，不维护封闭产品清单（当前如 536392、536744）

### 边界-05 "字面理解"的规则逐条确认
**问**：书面规则里反直觉 / 不合理的表述，是字面执行还是合理化推测？
**适用**：解读监管或渠道的通知类文件
**追问链**：列出所有"按字面理解"的点 → 每条向规则制定方显式确认 → 字面执行的代价是否可接受
**来源**：〔披露〕C12/C13——非固收类满 1 年**不**切换年化、成立不足阈值产品仍强制发 5 区间，均按字面理解列入确认清单

## 三、时序类

### 时序-01 计算触发与结果锁定
**问**：计算什么时候触发？算完能不能改？
**适用**：批量计算 / 月度加工类需求
**追问链**：全部输入到齐触发还是定时 → 算完锁定还是可反复跑 → 事后变更走什么审批
**来源**：〔净收入〕Q21——全部输入（净收入数据、银行部数据）到齐后一次性计算，当月结果即锁定，变更走重算审批

### 时序-02 跨期调整与历史重算
**问**：历史月份的结果发现错了怎么办？
**适用**：月度数据＋年度确认类流程
**追问链**：重算谁批准 → 重算影响下游哪些环节 → 快照取计算时点还是确认时点
**来源**：〔净收入〕Q19——考核确认是对当年各月拆分快照的追溯性确认、不改变配置；异议可触发历史月重算，须双批准

### 时序-03 节假日与非交易日
**问**：每个环节在节假日 / 非交易日的行为是什么？
**适用**：涉及定时任务、报送、月度处理的流程
**追问链**：停发还是顺延 → **同一通知里不同通道的规则是否不同** → 节前最后一天的特殊处理
**来源**：〔披露〕C10——F33 非交易日停发、BLTN 每天处理；同一份通知里两个通道节假日规则不同

### 时序-04 时间窗与截止时刻
**问**：对外发送的合法时间窗是什么？错过怎么办？
**适用**：对外 / 渠道报送类需求
**追问链**：窗口的精确边界（几点几分）→ 窗口外发送对方如何处理 → 补救路径（重传窗口与规则）
**来源**：〔披露〕BLTN 时间窗——建议 8:00 前批处理、硬限 14:00；当日 14:00 后发当日文件建行不处理，错发文件次日 08:00 前重传

## 四、权限与流程类

### 流程-01 每类操作的发起 / 确认 / 否决 / 归口
**问**：每类操作谁发起、谁确认、谁可否决、谁归口？
**适用**：任何跨部门流程
**追问链**：发起资格是否有限制（如最高比例部门）→ 确认是线上还是线下 → 归口部门的职责边界 → 全年随时还是定时窗口
**来源**：〔净收入〕Q7——部门间调整由当前归属比例最高的部门发起、涉事部门线上确认、创新发展部归口，全年随时可发起

### 流程-02 高风险操作的批准结构
**问**：哪类操作需要多方批准？是双人 / 双部门，还是任一即可？
**适用**：影响历史数据、对外报送、不可逆的操作
**追问链**：批准方是否覆盖利益冲突 → 单人可否执行 → 批准后如何留痕
**来源**：〔净收入〕Q19——历史月重算须计划财务部与创新发展部**双批准**

### 流程-03 审批留痕与线上线下边界
**问**：哪些调整走系统内审批流，哪些保持线下？
**适用**：现状为邮件 / 口头流程的系统化需求
**追问链**：现状哪些环节靠口头 / 邮件 → 上线后哪些收进系统 → 未收进的部分如何留痕
**来源**：〔净收入〕Q25/Q20——机构 / 券商的纯手工月度调整也须走系统内审批流留痕；调整确认走发起→待办→确认→生效

### 流程-04 数据可见范围分级
**问**：谁能看到哪些范围的数据？明细遮不遮？
**适用**：多部门共用的系统
**追问链**：按部门 / 按比例 / 按角色哪个维度划 → 明细行是否对无权部门遮蔽 → 汇总行是否可见
**来源**：〔净收入〕Q18——计财 / 创新发展部全量；市场部门可见范围＝本部门比例＞0 的产品全集，产品内各主体数据行不遮蔽

### 流程-05 与既有系统的职责边界
**问**：新系统与既有系统（如 able）的输入输出关系是什么？谁是权威源？
**适用**：替换或叠加既有流程的需求
**追问链**：输入是否仍依赖既有系统 → 结果是否回传 → **停用既有环节前，下游消费者是否确认已无**
**来源**：〔净收入〕Q27/C4——净收入输入仍从 able 导出、拆分结果不回传 able、本系统为唯一权威源；停止回传前须确认 able 上传数据无下游消费者

## 五、主数据类

### 主数据-01 维护方与变更流程
**问**：每项主数据谁维护？变更何时生效？
**适用**：存在映射表 / 清单 / 代码表的系统
**追问链**：变更走审批还是直接改 → 变更对历史数据的追溯效力 → 更新频率
**来源**：〔净收入〕Q16/Q33——地区→分公司映射、代销渠道清单、分公司代码均由银行业务部维护

### 主数据-02 每项输入的定位
**问**：每项输入是主数据、接口同步，还是人工提供？
**适用**：梳理输入清单时
**追问链**：为什么是这个定位（权威 / 时效 / 成本）→ 人工输入的校验规则 → 接口失败的兜底
**来源**：〔净收入〕Q33——分公司代码与地区对应规则＝主数据、产品信息表＝产品系统接口同步（C5 待确认）、销量表＝邮件人工提供

## 六、存量迁移类

### 迁移-01 存量与新增的边界事件
**问**：用什么事件划分存量与新增？
**适用**：承接既有业务的新系统
**追问链**：边界事件是否可观测（如"首次确认完成"）→ 边界上正在进行的流程算哪边 → 转换是一次性还是滚动
**来源**：〔净收入〕Q6——以产品首次完成系统内归属及比例确认为界，确认完成后即转存量

### 迁移-02 历史数据迁移范围
**问**：历史数据迁多少？更早的怎么办？
**适用**：含历史查询 / 考核追溯的系统
**追问链**：迁移范围依据什么（当年考核需要）→ 更早数据的查询需求走哪 → 迁移数据是否重算口径
**来源**：〔净收入〕Q26——仅迁当年已过月份的拆分快照（供年度考核确认），更早年份不迁

### 迁移-03 既有维护信息的一次性导入
**问**：现状靠人记 / Excel 维护的存量信息如何初始化？
**适用**：现状人工维护的配置类数据
**追问链**：导入前是否需业务部门确认 → 导入后与现状的差异如何处理 → 是否保留导入批次记录
**来源**：〔净收入〕Q17——机构 / 券商的历史维护信息一次性批量导入

## 七、对接类

### 对接-01 字段级映射与编码语义
**问**：与对方约定的每个字段：来源字段、编码表、长度格式，是否逐一过了？
**适用**：任何报文 / 文件对接
**追问链**：编码值语义我方理解与对方文档是否一致 → 字段长度与格式（日期、金额精度）→ 留空字段的占位方式
**来源**：〔披露〕C7/C8、〔净收入〕E6——YieldType 6/5 复权语义、TAID 长度与"005"段含义；管理费表实际字段为"销售商名称＋名称（地区名）"，与 xmind 写的"渠道名称"不符

### 对接-02 对方自行计算部分的口径对齐
**问**：对方用我方数据自己算的部分，口径是否与我方一致？
**适用**：我方供数、对方加工的协作
**追问链**：对方算法是否书面提供 → 口径不一致产生展示矛盾时谁负责 → 未来口径变更如何同步
**来源**：〔披露〕C5——建行按我方净值数据自行生成涨跌幅曲线，其口径是否同为累计净值待确认

### 对接-03 不发送内容的显式确认
**问**：文档里列了但决定不发的字段、对方未提的需求，是否向对方确认无要求？
**适用**：按己方理解裁剪对方文档时
**追问链**：裁剪清单逐项向对方确认 → "包括但不限于"类表述的覆盖范围怎么定 → 留空字段的语义
**来源**：〔披露〕C15——WPRegistrationCode 留空、YieldType 3/4/10/11/12 不发送，须向建行确认无额外要求；公告类别"包括但不限于"按四类全覆盖分析

## 八、术语与材料类

### 术语-01 废弃术语与统一叫法
**问**：现状材料里的旧叫法，目标系统统一为什么？旧词还出现在哪些环节？
**适用**：现状流程与新系统术语不一致时
**追问链**：旧术语出现在哪些表 / 系统 / 口头习惯 → 替换是否全量（含报表列名）→ 术语表登记 Avoid
**来源**：〔净收入〕Q17/E5——"打标签"废弃，统一为"归属及比例配置"；xlsx / xmind 中"拆分标签"一并修订

### 术语-02 勘误机制（含勘误本身可撤销）
**问**：发现材料错误怎么记录？勘误本身错了怎么纠正？
**适用**：多份源材料的需求梳理
**追问链**：勘误记编号 / 位置 / 原文 / 修正 / 理由 → 勘误可撤销、可修订 → 勘误是否同步回材料
**来源**：〔净收入〕E1/E2——E1 勘误（销量表挂错）次日撤销；E2 勘误（公式作废）修订为"公式保留、与总部份额模型融合"（见 ADR 0001）

### 术语-03 与合同 / 协议的优先级
**问**：系统规则与业务合同冲突时以谁为准？
**适用**：存在合同 / 补充协议约束的业务规则
**追问链**：冲突时系统阻断还是仅提示 → 冲突场景能否枚举 → 例外如何标记
**来源**：〔净收入〕Q5——与专户补充协议冲突时以协议为准，系统标记提示、不阻断

### 术语-04 范围外主体的显式排除
**问**：似在范围内又未明说的主体 / 部门 / 产品，是否逐一确认排除？
**适用**：范围按机构 / 部门 / 产品类型界定时
**追问链**：边界主体列出并确认 → 排除项转待确认清单（谁确认）→ 未来纳入的扩展方式
**来源**：〔净收入〕Q2/C1——网金部不在市场总部部门范围（转待确认 C1，业务部门核实）
