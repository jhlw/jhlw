# 产品谱系及产品画像设计方案

- 日期：2026-08-14
- 角色：需求分析人员（基金公司内部）
- 状态：已评审通过（会话内分节确认）

## 1. 背景与定位

基金公司内部产品数据现状零散、无统一标准。本方案为基金公司内部设计一套**产品谱系 + 产品画像**体系，定位为公司**产品主数据标准**：

- **交付形态**：两阶段交付。第一阶段产出业务规范（谱系 + 画像模板）；第二阶段产出系统概念设计（数据模型、功能模块、架构示意），不细化到页面与接口
- **产品范围**：公募为主，谱系结构预留私募资管/专户扩展位
- **画像用途**：两者兼顾——一个模板、两个视图。销售视图服务代销渠道产品准入与营销；内部管理视图服务立项、监控、考核、退出
- **整体方案**：一体化主数据方案（公司画像为全景、谱系为骨架、产品画像为血肉），一处定义、两处使用，杜绝两套数据打架

## 2. 整体架构：3 组件 + 1 扩展机制

产品主数据标准由以下部分构成（公司画像见第 5 章，与产品画像并列构成双层画像，四者关系见 2.5）：

### 2.1 谱系规范（骨架）

资产大类 → 策略赛道 → 产品三层树。每个产品必须且只能挂靠一个策略赛道节点。包含：节点定义规则、谱系编码规则、节点新增/停用的治理流程。

### 2.2 画像模板（血肉）

四组维度（基础 / 投资 / 风险+业绩 / 销售+运营）的字段全集。每个字段带 7 项元数据：字段名、业务定义、数据类型、枚举值、必填性、来源与维护（来源系统 + 维护责任部门 + 更新频率）、适用视图。

### 2.3 视图规范（投影）

- **销售视图**：从模板中选取渠道侧需要的字段，按"产品速览卡"组织，支撑代销渠道准入与营销材料输出
- **内部管理视图**：模板全量字段，按"产品档案"组织，支撑立项、监控、考核、退出
- 两视图是同一主数据的投影，不允许视图各自维护副本

### 2.4 扩展机制（预留位）

- **谱系扩展**：资产大类/策略赛道节点支持"产品类别"标记（公募/私募资管/专户），未来私募、专户以新分支接入，不动现有公募树
- **画像扩展**：模板按"字段组"管理，未来新增产品类别时增加字段组，不破坏既有字段定义

### 2.5 组件关系

四者构成**从大到小的三层**，画像模板为横切标准：

- **公司画像**（最上层）：公司全景（8 块，见第 5 章），回答"这家公司怎么样"
- **产品谱系**（中层）：资产大类 → 策略赛道 → 产品三层树，回答"公司产品版图什么样"，是公司画像之下、产品画像之上的组织骨架
- **产品画像**（底层）：单个产品的描述（实例 = 画像模板 × 产品），回答"这个产品怎么样"，通过"谱系编码"字段挂靠到谱系树节点
- **画像模板**（横切层）：贯穿公司画像与产品画像的字段定义与元数据标准，回答"画像能描述什么"，不含数据本身

四者关系：

```text
公司画像（公司全景，最上层）
    │ 按资产大类维度引用谱系；直接引用产品画像（旗舰产品，不复制）
    ▼
产品谱系（资产大类 → 策略赛道 → 产品，公司产品版图）
    │ 通过"谱系编码"字段挂靠
    ▼
产品画像（单产品描述 = 画像模板 × 产品）
画像模板 = 贯穿两层的字段定义标准（横切）
```

- **视图**（销售/内部）是公司画像与产品画像的字段投影，不存数据副本，决定"谁看到什么"
- **双层画像**：公司画像在上、产品画像在下，销售输出时"公司速览 + 产品速览卡"组合呈现

## 3. 谱系三层树设计

### 3.1 三层定义

- **资产大类（一级）**：按资产属性划分的四大类：货币（`10`）、固收（`20`）、权益（`30`，含混合型）、多资产/其他（`40`，QDII/另类/FOF 等）。每个大类有明确业务定义、目标客群、风险收益定位。归属冲突时**资格识别优先**（如具备养老目标基金资格的产品归入权益类 FOF 养老赛道），其余按投资策略归属；重叠冲突提交产品部 + 风控评审裁决，裁决结果沉淀为谱系案例库
- **策略赛道（二级）**：大类内共享同一投资策略内核的产品集合（如固收下的纯债、中短债、利率债、固收+）。入赛道三条件同时满足：同一策略标签（模板枚举）+ 同一业绩比较基准（基准体系一致即可，允许个别产品基准微小差异）+ 同一投研团队。团队拆分或基准重大变更触发赛道重组评审
- **产品（三级）**：单只公募基金，必须且只能挂靠一个策略赛道

### 3.2 编码规则

- 资产大类 2 位编码（`10` 货币、`20` 固收、`30` 权益、`40` 多资产/其他），策略赛道在其下 2 位（如固收下 `2001` 纯债、`2002` 中短债、`2003` 利率债、`2004` 固收+），共 4 位谱系编码；未来私募/专户分支启用独立编码段（如 `5x`/`6x` 起）
- 产品沿用现有基金代码，通过"谱系编码"字段关联，不重造产品代码
- 新增编码由产品部统一分配，在预留编码段内依次使用，一经启用**不回收复用**（历史产品追溯不受影响）

### 3.3 监管分类的位置

监管分类（股票型/债券型/混合型/货币型/QDII/FOF 等）作为**产品节点的属性字段**，与谱系并存。同一策略赛道内可以存在不同监管分类的产品（如固收大类下的纯债与一级债基）。谱系管"公司怎么看产品"，监管分类管"报送怎么报产品"。

### 3.4 扩展预留

每个策略赛道节点带"产品类别"标记（公募/私募资管/专户）。未来私募接入时新增资产大类/策略赛道分支（如"绝对收益"赛道），并约定：产品类别标记参与权限控制（私募画像视图仅限授权人员），不与公募树混挂。

### 3.5 治理规则

- **新增策略赛道**：需产品部 + 风控共同评审，明确策略内核与基准后方可建节点
- **产品换挂（换赛道）**：不允许单方调整，需评审并记录历史归属（生效日、原因、评审编号，永久留痕）；换挂自生效日起新业绩记新赛道，历史业绩保留在原赛道，考核报表按"归属时段 × 策略赛道"分段统计；**赛道整体换大类**属年度复盘中的边界复核事项，不设日常操作入口
- **年度谱系复盘**：覆盖度更新、旗舰评选、赛道边界复核、大类布局调整；事件触发评审覆盖新赛道、产品换挂、枚举变更、基准重大变更；季度同业数据更新属数据刷新，不走评审

## 4. 画像模板四组维度设计

模板按"字段组 → 字段"两级组织，每组字段携带统一元数据（见 4.5），便于双视图投影与未来扩展。

**字段全集 v1 在本阶段确定**：产品部牵头按维度组组织联合工作坊（基础/投资维度：产品部 + 投研；风险业绩：风控；销售运营：销售 + 运营），产出逐字段定义（含枚举值、必填性、来源与维护、适用视图），v1 定稿即模板基线版本，后续变更走版本管理。本节列代表字段，v1 全集由工作坊补全。

### 4.1 基础要素（骨架信息，双视图均可见）

产品代码、产品全称/简称、谱系编码、成立日、监管分类、存续规模、费率结构（管理费/托管费/申赎费）、托管人、基金经理。

### 4.2 投资要素（策略信息，销售视图取精炼版，内部视图全量）

投资目标、投资策略（文字描述 + 策略标签枚举）、业绩比较基准、投资范围、资产配置区间（如债券仓位 ≥80%）、投资限制条款。

### 4.3 风险+业绩要素（动态数据，双视图均见，口径分级）

- **本产品业绩**：风险等级（R1-R5）、历史最大回撤、年化波动率、区间收益率（**累计净值口径**）、适合客群（风险承受能力匹配）
- **同业比较**：
  - 同类产品定义（监管分类 + 策略标签，**默认采用银河证券分类口径**；个别场景需用晨星口径时，字段中注明所用分类体系，不得混用）
  - **TOP 排名**：本公司产品在同类中的名次（近 1 年 / 近 3 年区间收益率排名）、是否进入同类 TOP 10% / TOP 20% 区间、同类榜首/前五标杆产品参照（产品名称与收益率）——渠道营销的排名亮点素材
  - 同类均值与中位数（收益率、最大回撤）、同类规模排名
  - 外部评级（银河/晨星，如有）
- **更新频率**：本产品业绩月度更新，同业比较（含 TOP 排名）季度更新；数据来源为净值系统 + 第三方数据（Wind/晨星/银河）
- **口径要求**：TOP 排名必须注明统计口径（分类标准、统计区间、样本数量、数据截止日）；公司产品若不在统计样本内（如成立不足统计区间），标注"区间不足，未入榜"而非留空

### 4.4 销售+运营要素（业务运行信息，销售视图为主）

代销渠道清单、目标客群、申赎规则（确认日/赎回到账日）、开放期安排、分红方式、最近公告摘要。

### 4.5 字段元数据标准（每个字段必带 7 项）

| 元数据项 | 说明 |
| --- | --- |
| 字段名 | 唯一标识，英文/拼音码 |
| 业务定义 | 该字段在基金业务语境下的含义 |
| 数据类型 | 文本/数值/日期/枚举/区间 |
| 枚举值 | 枚举型字段的合法取值（如风险等级 R1-R5） |
| 必填性 | 必填/条件必填/选填 |
| 来源与维护 | 数据来源系统 + 维护责任部门 + 更新频率 |
| 适用视图 | 销售 / 内部 / 两者 |

**枚举字段权威来源**：风险等级采监管适当性标准（R1-R5 + 销售适当性匹配表）；监管分类随监管规则更新；策略标签由产品部定义、风控会签，发布后变更走模板版本管理，不直接改动在用枚举。

### 4.6 视图投影规则

销售视图 ≈ 标注"销售"的字段按"产品速览卡"排列（含同业比较摘要与 TOP 排名亮点）；内部视图 = 全量字段按"产品档案"排列。两个视图来自同一模板，任何字段值只有一份。

**字段边界规则**：默认所有字段双视图可见 + 黑名单例外（客户结构明细、渠道业绩、内部考核数据等敏感字段仅内部视图可见），规则先行，不用逐字段审批。

## 5. 公司整体画像（管理人层面，8 块）

### 5.1 公司基本情况

公司全称、成立时间、注册资本、股权结构（股东背景）、管理层（总经理/投研负责人）、持牌情况、分支机构。

### 5.2 经营概况

资产管理总规模（公募/私募/专户拆分）、规模行业排名；大类布局概览——以谱系资产大类为纲，展示各大类产品数量、规模、核心策略赛道；**谱系覆盖度**——已启用策略赛道数 ÷ 公司产品版图目标赛道数；空白大类/赛道清单是未来产品布局的候选方向，目标版图由产品部在年度产品规划中评审维护，覆盖度与同业头部公司产品布局的对比在年度规划时更新；投研团队（基金经理人数、平均从业年限、研究员覆盖面）。

### 5.3 公司整体业绩与同业比较

- 公司整体业绩：各资产大类整体收益率（累计净值口径）、规模加权整体业绩
- 同业比较：管理规模行业排名、各资产大类整体业绩同类百分位、公司旗下进入各类 TOP 榜的产品数量与分布、公司级获奖/评级（金牛奖、晨星公司评级等）

### 5.4 销售渠道情况

- 渠道结构：直销规模占比 vs 代销规模占比（内部视图可见全量数字，销售视图只展示占比结构）
- 代销渠道清单：按银行 / 券商 / 第三方互联网平台分类，每渠道标注：渠道类型、合作状态（存量合作/新接入/洽谈中）、代销本公司产品数量与规模、合作年限
- 渠道分层：核心渠道 / 成长渠道 / 培育渠道，分层标准以保有规模 + 资产大类契合度评定
- 渠道业绩：各渠道保有规模及占比、规模变动趋势——商业敏感信息，仅内部视图可见

### 5.5 旗舰/代表产品

各资产大类的代表产品清单，**年度评选**，量化标准：同类规模前 3 名 或 近 3 年区间收益率同类前 25%（累计净值口径），每大类至多 2 只；明星产品（市场知名度高）可由产品部提名例外进入，需风控确认业绩口径无误。旗舰产品信息**直接引用产品画像数据**（主数据联动），不另存副本。

### 5.6 客户结构

机构 vs 零售客户占比、客户数量、头部机构客户概况。客户明细为敏感信息，仅内部视图；销售视图只展示结构比例。

### 5.7 规模增长趋势

近 5 年历年管理规模曲线及增长率，数据来自基金业协会披露/公司年报，季度更新；销售视图展示趋势图，内部视图附明细数据。

### 5.8 与产品画像的关系

- 销售视图输出时"公司速览 + 产品速览卡"组合呈现，渠道先看管理人、再看产品
- 公司级"渠道布局"与产品级"代销渠道清单"**数据同源（渠道台账）**，产品画像的渠道字段从公司渠道台账引用，保证两处一致
- 公司级同业比较与产品级同业比较共用同一第三方数据源和分类口径，保证排名自洽

## 6. 数据流、维护机制与数据质量

### 6.1 数据流（来源 → 主数据 → 视图）

```text
基础要素   ← 产品生命周期系统 / TA 系统（自动同步，成立/变更时触发）
投资要素   ← 产品立项文档（人工录入，产品部）
风险+业绩  ← 净值系统（本产品业绩，月度自动）
            第三方数据 Wind/晨星/银河（同业比较，季度导入）
销售+运营  ← 渠道台账 / 运营台账（销售部、运营部，变更时更新）
公司画像   ← 基金业协会披露数据 / 公司年报 / 第三方数据（季度更新）
                ↓
          产品主数据（唯一值）
                ↓
      ┌───────┴───────┐
   销售视图        内部管理视图
（公司速览+产品速览卡）  （全档，内部授权）
```

### 6.2 维护机制

- **分工**：基础/投资要素归产品部，风险要素归风控部，业绩+同业归产品部（数据由投研支持），销售+运营归销售部/运营部，公司画像归产品部（季度更新）
- **触发方式**：静态字段走"产品成立/变更"流程；动态字段按频率自动刷新；同业比较季度导入
- **变更控制**：静态字段变更需产品部审批并留痕；动态数据不审批但留刷新日志

### 6.3 数据质量与异常处理

- **口径统一**：所有收益率字段一律累计净值口径，禁止在画像中出现复权/分红另口径数据
- **校验规则**：谱系编码必填且必须存在于谱系树；枚举字段（监管分类、风险等级）不得出现枚举外取值；区间数据必须携带统计区间与截止日
- **冲突仲裁**：当来源系统数据与已审批画像值冲突时，以**来源系统为准并告警产品部复核**，不静默覆盖；人工录入字段以审批记录为准
- **缺失处理**：第三方数据缺失（如无评级）时显式标注"暂无"，禁止留空或伪造默认值；同业比较无同类产品时降级为"无同类可比"并说明分类口径
- **发布闸门**：销售视图每次发布走审批链——产品部初审（口径与数据）→ 风控合规部终审（合规）→ 发布；每版本留档；口径类变更（如统计区间调整）需产品部负责人确认
- **口径联动**：公司画像中的业绩/排名与产品画像中的同业比较必须使用同一分类口径与同一数据时点，禁止两处排名口径不一致

## 7. 使用者与视图权限

### 7.1 内部使用者（8 类）

| 使用者 | 角色 | 使用的视图 |
| --- | --- | --- |
| 管理层 | 战略决策：公司全景、大类布局、规模趋势 | 内部视图（公司画像为主） |
| 部门总 | 业务管理：本部门产品的考核、监控、渠道表现 | 内部视图 |
| 市场部（营销人员） | 主力消费者：营销材料、渠道沟通、引用 TOP 排名 | 销售视图为主 + 内部视图（需授权） |
| 产品部 | 维护方：基础/投资要素维护、旗舰产品评选、谱系治理 | 内部视图（可编辑） |
| 投研部门 | 策略与业绩要素核对方：确认策略描述、业绩口径准确 | 内部视图（核对+修订建议） |
| 风控合规部 | 风险要素维护 + 销售材料合规审核、发布闸门审批 | 内部视图（审核权） |
| 运营部 | 运营要素维护（申赎规则、开放期、分红），净值数据来源方 | 内部视图（可编辑） |
| IT/数据部门 | 第二阶段主数据平台的建设与运维 | 系统层（无业务视图） |

### 7.2 外部使用者（2 类）

| 使用者 | 角色 | 使用的视图 |
| --- | --- | --- |
| 代销渠道 | 销售视图最终消费者：产品准入、适配合规销售 | 销售视图（经审批发布版） |
| 监管/审计（间接） | 画像口径与监管报送口径对齐（监管分类、净值口径） | 不直接使用，要求口径兼容 |

### 7.3 权限设计要点

- 双视图权限：销售视图对外发布需审批；内部视图按角色授权，客户结构/渠道业绩等敏感组仅管理层+相关部门可见
- 私募扩展预留：产品类别标记（公募/私募/专户）参与权限控制，私募画像仅授权人员可见

## 8. 第二阶段系统概念设计

### 8.1 数据模型（概念级，7 个核心实体）

```text
公司画像（公司全景，最上层）
        │ 按资产大类维度引用
        ▼
资产大类 ──1:n── 策略赛道 ──1:n── 产品
                                  │
                             1:n  │
                                  ▼
                          画像字段值 ──n:1── 画像字段定义（模板）
                                                  │
                                                  ▼
                            视图定义（销售/内部）= 字段子集投影
```

- **公司画像**：公司级独立实体组（8 块），位于层级最上层
- **资产大类 / 策略赛道 / 产品**：谱系树实体，产品挂靠唯一策略赛道
- **画像字段定义**：模板实体，承载字段元数据（7 项元数据标准）
- **画像字段值**：实例实体，产品 × 字段 → 值，含更新时间与来源标识
- **视图定义**：字段子集 + 排列规则，不存数据副本
- 辅实体：审批记录、操作审计日志

### 8.2 功能模块（7 个）

1. **谱系管理**：节点维护、编码管理、挂靠变更（历史留痕）
2. **画像模板管理**：字段组/字段定义、元数据维护、版本管理
3. **产品画像维护**：录入/同步/校验/审批
4. **公司画像维护**：季度更新、同业数据导入（含 TOP 排名计算）
5. **视图生成与发布**：速览卡生成、发布审批、版本留档
6. **权限与审计**：角色授权、敏感字段控制、操作留痕
7. **外部接口**：TA/净值系统同步、第三方数据导入（Wind/晨星/银河）、渠道输出

### 8.3 架构示意（分层）

```text
数据源层   TA系统 净值系统 渠道台账 第三方数据(Wind/晨星/银河) 人工录入
              ↓         ↓        ↓           ↓              ↓
主数据层    ┌─────────────────────────────────────────┐
            │  谱系  +  画像模板  +  产品画像  +  公司画像  │
            └─────────────────────────────────────────┘
视图服务层  字段投影 → 销售视图 / 内部视图 → 发布审批 → 版本留档
输出层     内部门户（管理层/部门/营销） 渠道输出 营销材料
```

- **系统形态建议**：主数据平台（核心）+ 视图服务，**优先挂靠公司现有数据中台**；无数据中台则独立建主数据模块（仍按中台式分层架构设计），避免建成孤立单业务系统
- **建设路线**：① 谱系与画像模板结构化（Excel/轻应用先行）→ ② 主数据平台 → ③ 渠道输出接口
- **本阶段边界**：只出到概念设计，不细化页面与接口

## 9. 界面原型产出（业务确认用）

原型以建信基金 2026Q2 真实公开数据为实例，经业务多轮迭代确认。原型文件归档于 `产品画像/prototypes/`：

| 原型 | 文件 | 版本 |
| --- | --- | --- |
| 公司画像速览页 | `公司画像速览页.html` | v14 |
| 产品谱系页 | `产品谱系页.html` | v6 |
| 产品画像页 | `产品画像页.html` | v16 |

**界面设计要点（原型迭代中确认，与规格章节对应）**：

- **公司画像页**：KPI 行 + 8 块卡片（产品线三分类与同业排名、本年度发行对比、收益变动、规模趋势、同业档位榜单、渠道业绩明细与变动、旗舰产品、客户明细）；资产大类分布环形图 + 各大类规模增比 vs 同业增比表；风险揭示采用**规模水位图**（产品规模条 + 清盘预警线，含小微/已清盘/缩水三级标记）；图表化原则：文字压减、重点用标记符号（⭐旗舰/红点小微/虚线空白）
- **产品谱系页**：资产大类 → 策略赛道条带视图（每行：编码 + 名称 + 规模占比条 + 赛道 chips 带说明）；治理操作内嵌行内（大类行「＋ 新增赛道」、赛道行「⇄ 产品换挂」）；覆盖度指标行（大类 4/4 · 赛道 14/16 · 挂靠率 100%）
- **产品画像页**：单页 + 双视图 tab 切换（销售视图 = 内部视图投影，隐藏红色锁定区）；**产品查询三路径**（搜索直达 / 谱系三级下拉 / 最近查看）；产品名旁标签胶囊（策略标签 + 类型 + ⭐旗舰）；风险等级块（R3 中风险 + 适合 C3 及以上）+ R1-R5 五档说明；亮点数字必带口径三要素（是什么/什么口径/截止日）；13 张内容卡：基础+仓位区间条、资产配置环形图、业绩+同业排名条、同业对比、同业竞品表、销售运营（渠道占比+同比+客群）、净值走势、规模走势、核心业绩+风险收益指标网格、前五大重仓、前十大持有人（内部）、申赎趋势、基金经理+在管产品清单；内部专属字段以红色虚线框标注（渠道业绩贡献、内部考核、持有人结构、前十大持有人明细等）

**数据口径约定（原型中落实）**：真实公开数据与示例数据在原型中明确区分标注（"示例"标记处以正式数据源为准）；收益率一律累计净值口径；同业比较默认银河分类。

## 10. 范围外事项（YAGNI）

以下内容明确不在本方案范围内：

- 系统落地阶段的页面原型与接口字段定义（属第二阶段之后的工作）
- 客服/投资者关系等次级使用者单独视图（从销售视图读取即可）
- 合规尽调资料（监管处罚记录、内控体系）——渠道尽调按既有合规流程提供，不进画像
- ESG/社会责任、业务资质牌照清单、品牌叙事等扩展内容，如需后续以字段组方式扩展
