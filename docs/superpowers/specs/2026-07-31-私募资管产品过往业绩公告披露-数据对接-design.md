## 一、背景与范围

### 1.1 需求来源

建行依据金规6号第四十六条，要求管理人通过 TA 系统和深圳通交互产品收益信息、运作报告、开放公告等内容。具体包含四类数据：

1. **渠道优先展示收益率** — 在产品列表及详情页展示，按固收/非固收、产品成立时间差异化计算
2. **成立以来涨跌幅净值曲线** — 所有存续期产品提供成立以来涨跌幅数据
3. **固定时间区间涨跌幅** — 成立以来、本周、本月、本季度、本年
4. **产品相关公告** — 募集公告、运作报告、开放期公告、分红公告等（盖章 PDF）

### 1.2 范围边界

本设计仅覆盖**数据对接层**——数据抽取、计算、文件生成、输出到指定目录。不含自有渠道前端展示，不含传输通道底层实现（TA 通道和深圳通本身已是现成设施，本方案只负责将文件放到对应目录）。

### 1.3 前置条件

| 项目 | 状态 |
|------|------|
| TA 系统数据库 | 现成，含产品信息、净值、估值表数据 |
| TA 传输通道 | 现成，每日自动从指定目录取 TXT 文件 |
| 深圳通传输通道 | 现成，每日自动从指定目录取 PDF 文件 |
| 交易日历 | 如有则复用，无则新建 |

### 2.2 模块职责

| 模块 | 职责 | 输入 | 输出 |
|------|------|------|------|
| **收益率计算引擎** | 根据产品类型和成立时间，计算各类收益率 | TA 库净值/估值数据 | 结构化收益率数组 |
| **TXT 文件生成器** | 将收益率数据按建行接口规范组装成 TXT | 收益率数组 | `OFD_{TAID}_005_{日期}_F33.TXT` |
| **公告文件处理器** | 扫描公告上传目录，校验并重命名 | 管理人上传的 PDF | 合规命名的 PDF |
| **调度器** | 按交易日历定时触发，管理重试和告警 | crontab/调度配置 | 执行日志 |

### 2.3 隔离原则

- 计算引擎只管数学，不关心文件格式
- 文件生成器只管格式组装，不关心数据怎么算的
- 如需加新代销渠道，只需新增生成器，计算引擎复用

## 三、收益率计算引擎

### 3.1 产品分类与渠道优先展示判定

```
                    产品成立时间 T（从成立日到当前交易日）
                              │
                 ┌────────────┴────────────┐
                 ▼                         ▼
           【固收类产品】              【非固收类产品】
                 │                         │
     ┌───────┬───┴───┬───────┐    ┌───────┴───────┐
     ▼       ▼       ▼       ▼    ▼               ▼
   T<1月  1月≤T<1年  T≥1年  任何T   T<6月         T≥6月
     │       │       │              │               │
     ▼       ▼       ▼              ▼               ▼
  不展示   成立以来   成立以来      不展示          成立以来
  收益率   涨跌幅    年化收益率    收益率          涨跌幅
          YieldType=2 YieldType=1              YieldType=2
```

**公式：**
- 涨跌幅 = (期末净值 / 期初净值) − 1
- 几何年化收益率 = (期末净值 / 期初净值)^(365 / 区间天数) − 1

### 3.2 每个产品生成的数据行

| 行 | 用途 | YieldTimeInterval | YieldType | YieldFrequency | ChannelRefFlag | 条件 |
|----|------|-------------------|-----------|----------------|----------------|------|
| 1 | 渠道优先展示 | `0`（成立至今） | `1`（年化）或 `2`（涨跌幅） | `0` | `1` | 满足展示条件时 |
| 2 | 成立以来涨跌幅 | `0`（成立至今） | `2`（涨跌幅） | `0` | `0` | 始终 |
| 3 | 本周涨跌幅 | `2`（周） | `2`（涨跌幅） | `0` | `0` | 始终 |
| 4 | 本月涨跌幅 | `3`（月） | `2`（涨跌幅） | `0` | `0` | 始终 |
| 5 | 本季度涨跌幅 | `4`（季度） | `2`（涨跌幅） | `0` | `0` | 始终 |
| 6 | 本年涨跌幅 | `6`（年） | `2`（涨跌幅） | `0` | `0` | 始终 |

> 始终 = 所有存续期产品。如成立不满对应间隔（如成立不足一周），对应行仍生成，YieldStartDate = 成立日，YieldExpireDate = 当前日。

### 3.3 净值取数规则

- 来源：TA 估值表
- 期初净值：产品成立日净值 / 本周一净值 / 月初首个交易日净值 / 季初首个交易日净值 / 年初首个交易日净值
- 期末净值：最新交易日净值
- 优先用**累计净值**（含分红再投资），单位净值作为兜底

### 3.4 计算流程（伪代码）

```
for each 存续期产品:
    product ← 查询产品类型、成立日期
    navs    ← 查询各时间窗口的期初净值、期末净值

    // 1. 渠道优先展示行（满足条件才生成）
    if 满足渠道优先展示条件:
        if 固收类 AND 成立 ≥ 1年:
            收益率 = 几何年化收益率(期初净值, 期末净值, 区间天数)
            yieldType = 1
        else:
            收益率 = 涨跌幅(期初净值, 期末净值)
            yieldType = 2
        writeRow(channelRefFlag = 1, ...)

    // 2. 固定时间区间（始终生成 5 行）
    for each (成立以来, 本周, 本月, 本季度, 本年):
        涨跌幅 = (期末净值 / 期初净值) − 1
        writeRow(channelRefFlag = 0, yieldType = 2, ...)
```

### 3.5 交易日历依赖

- 需要交易日历表来确定"本周一""月初首个交易日"等关键日期
- 如 TA 库无交易日历，新增一张表，覆盖 2008–2040 年，约 15 行逻辑（逐年生成）

## 四、TXT 文件生成器

### 4.1 文件规范

| 属性 | 值 |
|------|-----|
| 文件名 | `OFD_{TAID}_005_{YYYYMMDD}_F33.TXT` |
| 编码 | UTF-8（无 BOM） |
| 分隔符 | `|@|` |
| 换行 | LF（`\n`） |
| 空字段 | 连续两个 `|@|` 之间无内容，保留占位 |

### 4.2 单行字段顺序

```
TransactionCfmDate |@| FundCode |@| YieldFlag |@| Reserve1 |@| Reserve2 |@|
WPRegistrationCode |@| ChannelRefFlag |@| YieldTimeInterval |@| YieldType |@|
YieldStartDate |@| YieldExpireDate |@| YieldFrequency |@| YieldRatio
```

### 4.3 字段说明

| 序号 | 字段名 | 类型 | 说明 |
|------|--------|------|------|
| 1 | TransactionCfmDate | C(8) | 确认日期 YYYYMMDD |
| 2 | FundCode | C(6) | 基金代码 |
| 3 | YieldFlag | C(1) | 0-正 1-负 |
| 4 | Reserve1 | C(1000) | 备用1，当前留空 |
| 5 | Reserve2 | C(1000) | 备用2，当前留空 |
| 6 | WPRegistrationCode | C(20) | 理财产品登记编码 |
| 7 | ChannelRefFlag | C(1) | 0-不优先展示 1-优先展示 |
| 8 | YieldTimeInterval | C(2) | 收益率区间单位（见附录对照表） |
| 9 | YieldType | C(2) | 收益率类型 |
| 10 | YieldStartDate | C(8) | 收益率起始日期 YYYYMMDD |
| 11 | YieldExpireDate | C(8) | 收益率结束日期 YYYYMMDD |
| 12 | YieldFrequency | A(5) | 收益率频次 |
| 13 | YieldRatio | N(17,8) | 收益率数值（如 3.65% 填 0.0365） |

### 4.4 示例

```
20260731|@|001234|@|0|@||@||@|C1202500123|@|1|@|0|@|1|@|20240101|@|20260731|@|0|@|0.08500000
```

→ 基金 001234，渠道优先展示，成立至今年化收益率 8.5%，正收益

### 4.5 校验规则

- 文件名日期与内容 `TransactionCfmDate` 必须一致
- 每个产品至少 5 行（固定区间），最多 6 行（含渠道优先）
- `YieldRatio` 保留 8 位小数
- 每行字段数必须 = 13

### 4.6 生成时机

- 交易日 7:30 前文件到位（建行要求）
- 建议凌晨 2:00 批处理生成，留足缓冲
- 前一日晚上生成次日期文件名完全合规（见通知"合法情形一"）

## 五、公告 PDF 处理器

### 5.1 处理流程

```
管理人上传 PDF 到指定上传目录
    │
    ▼
┌─────────────────────┐
│ 扫描器（每 2 小时）   │  ← 配合建行 08:20/10:20/12:20/14:20 处理节奏
├─────────────────────┤
│ 1. 检查上传目录新文件  │
│ 2. 校验 PDF 有效性    │
│ 3. 检查电子章/实体章   │
│ 4. 组装文件名         │
│ 5. 复制到输出目录      │
│ 6. 记录日志           │
└─────────────────────┘
    │
    ▼
深圳通输出目录
BLTN_{TA}_{产品代码}_{YYYYMMDD}_{HHmmss}_{原始文件名}.pdf
```

### 5.2 文件名组装规则

```
BLTN_{2位TA代码}_{6位产品代码}_{当前日期}_{时分秒}_{原始文件名}.pdf

示例：
  管理人上传："建信纯债债券A_2024年度运作报告.pdf"
  输出：       "BLTN_01_001234_20260731_083000_建信纯债债券A_2024年度运作报告.pdf"
```

### 5.3 关键约束

| 约束 | 规则 |
|------|------|
| 传输窗口 | 每天 08:00–14:00，文件名日期 = 当前日期 |
| 重传 | 14:00 前可覆盖，14:00 后当天不再处理 |
| 盖章 | 实体章或电子章均可，电子章需提前备注 |
| TA 代码 | 固定 2 位，与 TA 系统配置保持一致 |

### 5.4 输出目录结构

```
/output/
├── ta/                                    ← TA 通道（自动取走）
│   └── OFD_01_005_20260731_F33.TXT
├── szt/                                   ← 深圳通通道（自动取走）
│   └── BLTN_01_001234_20260731_083000_运作报告.pdf
├── archive/                               ← 本地归档（7 天保留）
│   ├── ta/
│   └── szt/
└── upload/                                ← 管理人公告上传目录
    └── (待处理PDF文件)
```

## 六、调度策略

### 6.1 调度时间线

```
01:30  │ 收益率计算引擎启动
       │ ├─ 从TA库拉取所有存续产品最新净值
       │ ├─ 检查交易日历：今天是否是交易日？
       │ │  └─ 是 → 正常生成
       │ │  └─ 否 → 跳过，退出
       │ └─ 计算全量产品收益率
       │
02:00  │ TXT生成器启动
       │ ├─ 组装文件名（日期=该交易日）
       │ ├─ 逐产品写行
       │ ├─ 校验行数、字段数
       │ └─ 写出到 /output/ta/
       │
06:30  │ 失败重试窗口（预留）
       │
07:00  │ 最终检查：文件是否存在、大小是否合理
       │ └─ 告警触发条件：无文件 / 0行 / 产品数 < 预期的70%
       │
07:30  │ ← TA通道取走文件截止（建行要求）
       │
──────────────── 分隔线 ────────────────
       │
08:00  │ 公告扫描器每2小时启动一次
10:00  │ (扫描 upload/，处理新PDF)
12:00  │
14:00  │ 最后一次扫描（当日截止）
14:20  │ ← 深圳通通道取走文件
```

### 6.2 触发方式

- 业绩 TXT：Linux cron `30 1 * * 1-5` / Windows 任务计划，由调度器入口脚本触发
- 公告 PDF：Linux cron `0 8-14/2 * * *`，每 2 小时扫描一次

## 七、异常处理与日志

### 7.1 异常处理策略

| 场景 | 处理策略 |
|------|---------|
| 非交易日 | 不生成文件，日志 `SKIP:非交易日`，正常退出码 0 |
| 某产品净值缺失 | 跳过该产品，日志 `WARN`，其余产品正常生成 |
| 某产品净值异常（单日涨跌幅 > 20%） | 仍生成行但日志标记 `ALERT`，人工复核 |
| TXT 校验失败（行数/字段数错误） | 删除已生成文件，日志 `ERROR`，触发告警 |
| 公告 PDF 无效 | 保留在上传目录不移动，日志 `WARN: PDF校验失败:{原因}` |
| 输出目录不可写 / 磁盘满 | 日志 `FATAL`，立即告警 |
| TA 数据库连接失败 | 重试 3 次，间隔 60s，仍失败则 `FATAL` 告警 |

### 7.2 日志格式

```
[2026-07-31 01:30:01] INFO  收益率计算开始 | 交易日=20260731 | 产品总数=42
[2026-07-31 01:30:15] INFO  └─ 固收类=28, 非固收类=14
[2026-07-31 01:30:22] WARN  └─ 产品 001235 净值缺失，跳过
[2026-07-31 01:30:45] INFO  计算完成 | 成功=41, 跳过=1, 耗时=44s
[2026-07-31 02:00:01] INFO  TXT生成开始 | 目标文件=OFD_01_005_20260731_F33.TXT
[2026-07-31 02:00:03] INFO  └─ 写入 41 产品, 235 行数据
[2026-07-31 02:00:03] INFO  校验通过 | 文件名合规 | 字段数=13/行 | 文件大小=18.2KB
[2026-07-31 02:00:03] INFO  生成完成 → /output/ta/OFD_01_005_20260731_F33.TXT
[2026-07-31 07:00:00] INFO  最终检查 | 文件存在 | 大小=18.2KB | 产品数=41 ✓
[2026-07-31 08:00:00] INFO  公告扫描开始 | 扫描目录=/output/upload/
[2026-07-31 08:00:01] INFO  └─ 处理 1 个新PDF → BLTN_01_001234_20260731_080001_运作报告.pdf
```

### 7.3 告警规则

| 级别 | 条件 | 通知方式 |
|------|------|---------|
| FATAL | 文件未生成 / 磁盘满 / 数据库连不上 | 短信 + 邮件 |
| ERROR | 校验失败 / 产品数比昨天少 30% 以上 | 邮件 |
| WARN | 个别产品跳过 / PDF 校验失败 | 仅日志 |
| INFO | 正常执行摘要 | 打印到 stdout |

## 八、技术选型

| 项 | 建议 | 理由 |
|-----|------|------|
| 语言 | Python 3 | 团队 Python 栈，生态成熟 |
| 调度 | cron（Linux）或 Windows 任务计划 | 最简单可靠 |
| 数据库 | `psycopg2` 或 `pymysql` | 视 TA 库类型（PostgreSQL / MySQL） |
| 交易日历 | 单表 `trading_calendar` | 约 15 行逻辑即可生成全部日期 |
| 配置管理 | YAML 配置文件 | 可读性好，方便运维修改 |
| 日志 | Python `logging` | 标准库，无额外依赖 |
