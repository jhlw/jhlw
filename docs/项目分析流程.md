# 项目分析流程（需求分析全链路）

2026-11-24 整理，来源＝业绩比较基准项目全程实践＋当日系列定夺。配套资产：[需求拷问题库](需求拷问题库.md)（问清楚）、[业务解决方案模板](业务解决方案模板.md)（写清楚）、skill 分工记忆（图示四车道/写作分工）。**新项目分析按此流程走**，阶段可按项目类型裁剪（全新建设裁现状章、纯咨询无原型阶段等）。

## 流程总览

| 阶段 | 输入 → 输出 | 主力 skill | 方法/资产 |
|---|---|---|---|
| 0 接件与解读 | 需求材料 → 项目目录＋旧工具/监管解读 | xlsx、pdf、docx、agent-reach | 权威源优先级；总结≠原文 |
| 1 需求拷问 | 材料＋题库 → 澄清定稿＋C 表待确认 | grilling / grill-with-docs（＋domain-modeling） | docs/需求拷问题库.md |
| 2 方案撰写 | 澄清定稿 → 业务解决方案 docx | docx | docs/业务解决方案模板.md |
| 3 实盘验算 | 方案口径 → 真实产品样例 xlsx | xlsx（＋Excel COM）、agent-reach | 公式链同构；decimal 精度 |
| 4 原型与 UX | 方案 → 界面原型＋用例流 | frontend-design、ux-flow-designer、ui-ux-pro-max | 原型↔方案双向同步 |
| 5 图示与汇报 | 方案/样例 → 图＋汇报 PPT | 图示四车道＋PPT 四件＋写作分工 | 汇报必带请求定夺清单 |
| 6 PRD 与交接 | 方案＋原型 → PRD → 开发工单 | product-manager-skill、speckit | 开放问题归零才拆票 |
| 7 复盘与资产化 | 缺陷/新模式 → 题库/模板回填 | commit | 只增不删 |

## 阶段细则与路径

### 0 接件与解读
- 建项目目录 `项目/<项目名>/`；解读文档与源文件同目录
- 旧工具 xlsm：**xlsx** skill＋oletools `VBA_Parser.extract_macros()` 提宏、openpyxl `read_only=True` 读结构（勿逐行回退）
- 扫描版监管附件：**pdf** skill OCR；**公式级内容必须对原文逐页核查**（附件3 连乘规则曾被总结漏掉）
- 公开源佐证（代码库/披露数据）：**agent-reach**
- 方法：权威源优先级＝监管原文＞合同条款＞业务定稿＞系统现状；冲突按优先级裁决并留痕

### 1 需求拷问
- 开场提示词见题库用法节：**grilling 引擎＋题库种子**；有输入文档用 **grill-with-docs** 先喂材料，纯口述用 grilling
- 术语密集型项目同时调 **domain-modeling** 维护项目 `CONTEXT.md` 术语表（含 Avoid 禁用叫法），供模板「名字解释」章取用
- 定稿格式：Q 号/问题/推荐/定夺/**定夺人/日期/依据**；待确认项列 C 表带归口
- 纪律：**定稿当天回填题库**（新题带真实来源，候选类别对照核销）；业务侧催办等用户通知，不自动触发
- 路径：澄清清单 `项目/<项目名>/`（md＋docx 双版，docx skill 生成）

### 2 方案撰写
- 按模板八章骨架：背景→名字解释→现状描述→业务目标（含目标与现状差异）→现状改动点→业务流程→计算公式→业务功能设计
- 每口径/公式注定稿来源（Q 号/确认日期/原材料条款）；开放问题用「> **问题：**…（日期＋状态）」
- docx 工艺：新文档 md→pandoc；**用户审核过的 docx 走 unpack→改 XML→pack**（保批注/格式/插图），验证三板斧＝python-docx 可读＋pandoc diff 范围＋术语残留扫描
- 版本纪律：最新版就地维护、不多版并存；重大修订留修订说明；术语改名 grep 零残留
- 路径：`项目/<项目名>/<方案名>vX.Y.docx`

### 3 实盘验算
- 真实产品样例验证口径（基准项目＝000270 对披露数据逐日比对）；**Python 计算链与 Excel 公式链逐步同构**（舍入顺序一致）
- 高精度（>15 位有效数字，如 30 位精度定稿）用 **Python decimal**——Excel/float64 只有约 15–17 位，ROUND(,30) 名义 30 位实际截断；Excel COM 仅做显示层重算验证
- 多表工作簿交付前核对各表行数与首末日期对齐；文件占用致损坏时从源重建
- 纪律：**样例随方案口径同步**——样例滞后＝口径未验证；新口径（如货基）须找对应类型真实产品补实证
- 路径：`项目/<项目名>/<产品代码>_样例.xlsx`

### 4 原型与 UX
- 正式交付原型：**frontend-design**（单文件离线 HTML）；用例流/线框：**ux-flow-designer**；设计系统 MASTER.md：**ui-ux-pro-max**
- 渲染验证：Playwright MCP（禁 file: 协议，本地起 http.server）或 webapp-testing
- 纪律：原型↔方案**双向同步**，双方引用章节号；原型目录从项目既有约定（界面原型/ 或 prototypes/）
- 路径：`项目/<项目名>/界面原型/`、`ux-flows/`、`design-system/`

### 5 图示与汇报
- 图示四车道（2026-11-24 定夺）：正式交付图→**baoyu-diagram**；手绘讨论稿→**excalidraw-diagram-generator**；业务流程泳道→**process-mapper**；架构/数据流讲解页→**archify**；diagram-design 留个人知识图
- PPT 四件：正式汇报→**mckinsey-consultant-11**；网页浏览版→**guizang-ppt-skill**；模板填充/旁白→**ppt-master**；就地小改→**pptx**
- 文字汇报：status-report／internal-comms；对外终稿去 AI 味：**humanizer-zh**
- 纪律：**汇报必带请求定夺清单**（C6 就是汇报会后定夺的）；PPT 交付物默认不入 git，例外由用户定夺
- 路径：`diagram/`、`ppt/`、`阶段性汇报/`（项目目录下）

### 6 PRD 与开发交接
- **product-manager-skill** 出 PRD（文体与业务解决方案分工：方案讲口径、PRD 讲功能与验收，不混用）
- 门禁：PRD 开放问题/拍板时限表**归零后才拆票**（如历史回补范围、管理台取舍须开发启动前定夺）
- **speckit** specify→plan→tasks→taskstoissues 拆票，issue 跟踪走 gh CLI（见 docs/agents/issue-tracker.md）
- 路径：`项目/<项目名>/docs/prd/`

### 7 复盘与资产化
- 缺陷复盘（UAT/上线问题）→ 回溯「当初该问没问的」**回填题库**
- 新结构模式/写作教训 → **回填模板**（注来源〔项目名〕，只增不删）
- 项目记忆＋索引更新；**commit** skill 分组提交（Conventional＋emoji 风格）
- 记忆只是索引，定稿前核实文；临时文件用完即删
